OLAP vs OLTP

OLTP (Online Transaction Processing)
OLAP (Online Analytical Processing)

| 구분        | OLTP                      | OLAP                               |
| --------- | ------------------------- | ---------------------------------- |
| 목적        | 실시간으로 핵심 비즈니스 운영을 제어하고 처리 | 계획 수립, 문제 해결, 의사결정 지원, 숨겨진 인사이트 발견 |
| 데이터 갱신    | 사용자가 직접 수행하는 짧고 빠른 업데이트   | 스케줄된 장시간 배치 작업을 통해 주기적으로 데이터 갱신    |
| 데이터베이스 설계 | 효율성을 위한 정규화된 데이터베이스       | 분석을 위한 비정규화된 데이터베이스                |
| 공간 요구사항   | 과거 데이터를 아카이빙하면 일반적으로 작음   | 대규모 데이터 집계로 인해 일반적으로 큼             |


--


| 구분      | OLTP                                      | OLAP                                   |
| ------- | ----------------------------------------- | -------------------------------------- |
| 백업 및 복구 | 비즈니스 연속성과 법·거버넌스 요구사항을 충족하기 위해 정기적인 백업 필요 | 정기 백업 대신 필요 시 OLTP 데이터베이스에서 데이터 재로딩 가능 |
| 생산성     | 최종 사용자 생산성 향상                             | 비즈니스 관리자, 데이터 분석가, 임원 생산성 향상           |
| 데이터 관점  | 일상적인 비즈니스 트랜잭션 목록                         | 기업 데이터의 다차원적 관점                        |
| 사용자 예시  | 고객 응대 직원, 사무원, 온라인 쇼핑 고객                  | 데이터 분석가, 비즈니스 분석가, 임원 등 지식 근로자         |

지정한 컬럼을 기준으로 관련 데이터가 물리적으로 함께 저장됩니다.

컬럼의 순서가 중요합니다.

지정한 컬럼의 순서에 따라 데이터의 정렬 순서가 결정됩니다.

클러스터링은 다음과 같은 쿼리 성능을 향상시킵니다:

필터(Filter) 쿼리

집계(Aggregate) 쿼리

데이터 크기가 1GB 미만인 테이블은 파티셔닝이나 클러스터링을 적용해도 유의미한 성능 개선이 나타나지 않습니다.

최대 4개의 클러스터링 컬럼을 지정할 수 있습니다.


GEM> 해석
제시해주신 내용은 Google BigQuery의 클러스터링(Clustering) 핵심 개념들을 정리한 것입니다. 요청하신 대로 각 항목에 대한 상세한 해석과 설명을 정리해 드립니다.

1. 데이터 웨어하우스와 클러스터링의 역할
"Columns you specify are used to colocate related data"

해석: 지정한 컬럼들을 기준으로 관련 데이터들을 물리적으로 같은 위치에 함께 저장합니다.

설명: 비슷한 값을 가진 데이터들이 나란히 저장되기 때문에, 특정 범위를 조회할 때 불필요한 데이터를 읽지 않아도 되어 효율적입니다.

2. 컬럼 순서의 중요성
"Order of the column is important / The order of the specified columns determines the sort order of the data."

해석: 지정하는 컬럼의 순서가 매우 중요하며, 이 순서가 곧 데이터의 정렬 순서를 결정합니다.

설명: 예를 들어 (날짜, 고객ID) 순으로 클러스터링을 하면 날짜별로 먼저 정렬되고, 그 안에서 고객ID별로 정렬됩니다. 쿼리 실행 시 첫 번째 컬럼부터 순서대로 필터링에 사용할 때 성능이 극대화됩니다.

3. 성능 최적화 (성능이 향상되는 경우)
"Clustering improves: Filter queries / Aggregate queries"

해석: 클러스터링은 필터(WHERE 절) 및 집계(GROUP BY 절) 쿼리의 성능을 향상시킵니다.

설명: * 필터 쿼리: 데이터가 정렬되어 있으므로 특정 조건에 맞는 블록만 골라 읽을 수 있습니다.

집계 쿼리: 동일한 값을 가진 데이터들이 뭉쳐 있어 합계, 평균 등을 계산할 때 탐색 범위가 줄어듭니다.

4. 데이터 크기에 따른 효율성
"Table with data size < 1 GB, don’t show significant improvement with partitioning and clustering"

해석: 테이블 크기가 1GB 미만인 경우, 파티셔닝이나 클러스터링을 적용해도 성능 향상이 미미합니다.

설명: 데이터량이 적으면 전체를 다 읽는 것(Full Scan)과 인덱싱된 영역을 찾는 비용의 차이가 거의 없기 때문에, 관리 비용만 늘어날 수 있습니다.

5. 제약 조건
"You can specify up to four clustering columns"

해석: 클러스터링 컬럼은 최대 4개까지만 지정할 수 있습니다.

설명: 가장 자주 사용되고 변별력이 높은 컬럼 위주로 상위 4개를 전략적으로 선택해야 합니다.

💡 요약하자면
BigQuery 클러스터링은 데이터를 특정 순서대로 정렬하여 쿼리 비용을 줄이고 속도를 높이는 기술입니다. 특히 대용량 테이블에서 자주 쓰이는 필터 조건의 컬럼을 순서대로 지정하는 것이 핵심입니다.

혹시 이 개념을 바탕으로 실제 BigQuery SQL 생성 예시나 테이블 생성 코드가 필요하신가요? 원하신다면 전체 코드를 작성해 드릴 수 있습니다.

간단요약


GEM> 빅쿼리의 성능과 비용을 결정하는 핵심 개념 3가지를 아주 쉽게 요약해 드립니다.

1. 파티셔닝 (Partitioning)
개념: 커다란 테이블을 특정 기준(주로 날짜)에 따라 거대한 칸막이로 나누는 것입니다.

효과: 쿼리할 때 WHERE 절에 날짜를 넣으면, 해당 날짜의 "칸막이"만 읽습니다.

비유: 도서관에서 책을 **'연도별'**로 서가를 나누어 놓은 것과 같습니다. 2024년 책을 찾을 때 2000~2023년 서가는 쳐다보지도 않아도 됩니다.

장점: 스캔하는 데이터 양을 획기적으로 줄여 비용을 직접적으로 아껴줍니다.


2. 클러스터링 (Clustering)
개념: 각 파티션 내부에서 데이터를 특정 컬럼(예: VendorID) 기준으로 비슷한 것끼리 뭉쳐서 정렬해두는 것입니다.

효과: 특정 값을 찾을 때 데이터가 물리적으로 모여 있어 훨씬 빠르게 찾아냅니다.

비유: 연도별 서가 안에서 책들을 **'저자 이름순'**으로 정렬해 놓은 것과 같습니다. 특정 저자의 책을 찾을 때 서가 처음부터 끝까지 다 뒤질 필요가 없습니다.

장점: 복잡한 필터링이나 집계(Group By) 성능을 높여줍니다.

3. 자동 클러스터링 (Automatic Clustering)
개념: 사용자가 클러스터링 설정을 해두면, 데이터가 새로 들어오거나 수정될 때 빅쿼리가 백그라운드에서 알아서 다시 정렬해주는 기능입니다.

효과: 데이터가 쌓이면서 정렬이 흐트러져도 사용자가 수동으로 VACUUM이나 재정렬 명령을 내릴 필요가 없습니다.

장점: 관리의 편의성. 사용자는 신경 쓰지 않아도 빅쿼리가 최적의 성능을 유지하도록 뒤에서 계속 청소(Re-org)를 해줍니다.

💡 한 줄 요약
파티셔닝으로 읽을 범위를 크게 걷어내고, 클러스터링으로 그 안에서 필요한 것만 쏙 골라내며, 자동 클러스터링으로 이 상태를 편하게 유지한다!
