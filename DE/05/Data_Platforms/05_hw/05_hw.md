## 📝 Homework Solutions & Technical Insights

### Question 1. Bruin Pipeline Structure
In a Bruin project, what are the required files/directories?

1. `bruin.yml` and `assets/`
2. `.bruin.yml` and `pipeline.yml` (assets can be anywhere)
**> 3. .bruin.yml and pipeline/ with pipeline.yml and assets/**
4. `pipeline.yml` and `assets/` only

> **Technical Insight:** The `.bruin.yml` (hidden file) is essential for environment/connection settings, while the `pipeline/` directory acts as the root for orchestration and data assets.

### Question 2. Materialization Strategies
You're building a pipeline that processes NYC taxi data organized by month based on `pickup_datetime`. Which incremental strategy is best for processing a specific interval period by deleting and inserting data for that time period?

1. `append` - always add new rows
2. `replace` - truncate and rebuild entirely
**> 3. time_interval - incremental based on a time column**
4. `view` - create a virtual table only

> **Technical Insight:** `time_interval` is the go-to for NYC taxi data because it allows a "Delete-and-Insert" pattern. It efficiently updates a specific time window without the cost of a full table rebuild.

### Question 3. Pipeline Variables
How do you override this when running the pipeline to only process yellow taxis?

1. `bruin run --taxi-types yellow`
2. `bruin run --var taxi_types=yellow`
**> 3. bruin run --var 'taxi_types=["yellow"]'**
4. `bruin run --set taxi_types=["yellow"]`

> **Technical Insight:** Since the variable is defined as an array, the CLI override must use JSON syntax. Single quotes are mandatory to ensure the shell passes the brackets and double quotes correctly.

### Question 4. Running with Dependencies
You've modified the `ingestion/trips.py` asset and want to run it plus all downstream assets. Which command should you use?

1. `bruin run ingestion.trips --all`
2. `bruin run ingestion/trips.py --downstream`
3. `bruin run pipeline/trips.py --recursive`
**> 4. bruin run --select ingestion.trips+**

> **Technical Insight:** Bruin uses graph selection syntax where the `+` suffix includes all downstream (child) dependencies. This ensures consistency across the entire data lineage after a change.

### Question 5. Quality Checks
You want to ensure the `pickup_datetime` column in your trips table never has NULL values. Which quality check should you add to your asset definition?

1. `name: unique`
**> 2. name: not_null (or not_null: true)**
3. `name: positive`
4. `name: accepted_values, value: [not_null]`

> **Technical Insight:** `not_null` is a fundamental gatekeeper. In this pipeline, it ensures every trip has a valid timestamp before it moves into the staging and reporting layers.

### Question 6. Lineage and Dependencies
After building your pipeline, you want to visualize the dependency graph between assets. Which Bruin command should you use?

1. `bruin graph`
2. `bruin dependencies`
**> 3. bruin lineage**
4. `bruin show`

> **Technical Insight:** The `lineage` command is vital for understanding "Data Ancestry," allowing engineers to trace the flow and identify impact areas when an upstream asset changes.

### Question 7. First-Time Run
You're running a Bruin pipeline for the first time on a new DuckDB database. What flag should you use to ensure tables are created from scratch?

1. `--create`
2. `--init`
**> 3. --full-refresh**
4. `--truncate`

> **Technical Insight:** In a fresh environment (like our new DuckDB setup), `--full-refresh` is the standard flag to drop existing structures and force-create everything according to the latest code definitions.
