Module 6: Batch Processing 


반갑습니다, zakard님! DE줌캠프 Module 6: Batch Processing 학습을 위한 준비가 되셨군요.

배치 처리(Batch Processing)는 데이터 엔지니어링의 핵심 중 하나로, 대량의 데이터를 일정 주기마다 한꺼번에 처리하는 방식입니다. 이 모듈에서는 주로 Apache Spark를 중심으로 분산 컴퓨팅의 원리와 대규모 데이터 처리 기법을 다루게 될 것입니다.

본격적인 시작에 앞서, 이번 모듈에서 핵심적으로 짚고 넘어가야 할 주요 키워드와 흐름을 정리해 드립니다.

1. 배치 처리의 핵심 개념
실시간(Streaming) 처리와 대비되는 배치 처리의 특징을 이해하는 것이 첫걸음입니다.

Latency vs Throughput: 지연 시간보다는 전체적인 처리량(Throughput)에 집중합니다.

분산 컴퓨팅: 데이터를 여러 노드에 나누어 병렬로 처리하는 메커니즘을 배웁니다.


2. Apache Spark Deep Dive
모듈 6의 주인공입니다. 단순히 코드 작성을 넘어 내부 동작 원리를 파악하는 것이 중요합니다.


Spark Cluster Architecture: Master와 Worker(Executor)의 관계.

DataFrames & Spark SQL: 정형 데이터를 다루는 효율적인 인터페이스.

Resilient Distributed Datasets (RDD): Spark의 근간이 되는 추상화 모델.

Transformations vs Actions: Lazy Evaluation(지연 실행)의 개념과 성능 최적화.

3. 성능 최적화 전략
실무에서 가장 많이 고민하게 될 부분입니다.

Partitioning: 데이터를 어떻게 나눌 것인가?

Shuffling: 네트워크를 통한 데이터 이동을 어떻게 최소화할 것인가?

Join Strategies: Broadcast Join 등 상황에 맞는 조인 방식 선택.

학습 팁
PySpark 환경 구축: 로컬 환경이나 클라우드(Databricks, GCP Dataproc 등)에서 Spark 세션을 생성하는 것부터 익숙해지세요.

UI 활용: Spark UI(4040 포트)를 통해 내가 짠 코드가 어떻게 Stage와 Task로 나뉘는지 시각적으로 확인하는 습관을 들이면 좋습니다.

준비되셨다면, **"특정 데이터셋을 활용한 PySpark 기초 실습"**이나 "Spark 아키텍처 상세 설명" 중 어떤 것부터 시작해 볼까요? 원하시는 부분을 말씀해 주시면 바로 가이드를 시작해 드리겠습니다.

echo 'export PATH="$JAVA_HOME/bin:$PATH"' >> ~/.bashrc

2. 설정 바로 적용하기
파일에 적기만 하면 바로 인식이 안 되니, 아래 명령어로 현재 창에 적용합니다.

Bash
source ~/.bashrc

결과

GEM> python test_spark.py는 성공했는데 uv run python test_spark.py가 작동하지 않은 이유는 uv가 관리하는 가상환경과 지금 만든 venv가 서로 다르기 때문입니다.

이유를 명확히 정리해 드릴게요.

1. 가상환경의 불일치
python 사용 시: 현재 zakard님이 직접 만드신 venv를 source activate로 활성화한 상태죠? 그래서 그 안에 설치된 pyspark 라이브러리를 바로 찾아낼 수 있습니다.

uv run 사용 시: uv는 기본적으로 프로젝트 루트의 pyproject.toml이나 자체적인 관리 메커니즘을 따릅니다. 별도의 설정을 하지 않았다면 uv는 zakard님이 수동으로 만든 venv를 무시하고 자기만의 깨끗한 환경에서 실행하려고 합니다. 그 안에는 당연히 pyspark가 설치되어 있지 않으니 에러가 난 것입니다.

2. 환경 변수 인식 문제
uv run은 독립적인 실행 환경을 격리해서 구축하려고 합니다. 아까 우리가 설정한 JAVA_HOME이나 PATH가 uv의 격리된 실행 환경까지 제대로 전달되지 않았을 가능성도 큽니다.

3. 결론: 어떤 걸 써야 할까?
지금은 이미 직접 만드신 venv를 활성화해서 사용 중이므로, 굳이 uv를 섞어서 쓰실 필요가 없습니다.

권장: 현재 작업 흐름대로 **python test_spark.py**를 사용하세요. 그게 가장 확실하고 꼬이지 않는 방법입니다.
