자신만의 검색 엔진 만들기 (Build Your Own Search Engine)

강사: Alexey Grigorev

0. 개요
이 워크숍은 본 코스 시작 전, RAG(검색 증강 생성) 시스템의 가장 핵심적인 구성 요소인 **'검색(Retrieval)'**의 원리를 이해하기 위해 마련되었습니다. 우리는 실제 서비스용(Production)은 아니지만, 검색의 기본 원리를 완벽히 보여주는 인메모리(In-memory) 검색 엔진을 직접 구현해 볼 것입니다.

1. RAG 시스템과 검색의 역할
RAG 시스템은 사용자가 자신의 데이터와 대화할 수 있게 해줍니다.

작동 방식: 사용자가 질문을 하면, 데이터베이스(우리의 경우 FAQ 문서)에서 가장 관련 있는 문서 5개를 찾습니다(Retrieval). 이 문서들을 프롬프트에 '컨텍스트'로 넣어 LLM(OpenAI 등)에게 전달하면, 모델이 그 정보를 바탕으로 답변을 생성합니다(Generation).

검색의 두 가지 유형:

텍스트 검색(Text Search): 키워드가 정확히 일치하는지 확인합니다. (예: 'Join', 'Course')

의미/벡터 검색(Semantic/Vector Search): 단어는 다르지만 의미가 유사한 것을 찾습니다. (예: 'Enroll'과 'Join')


2. 환경 설정 및 데이터 준비
우리는 FAQ 데이터(Data Engineering Zoomcamp 등)를 사용하여 검색 엔진을 만듭니다.

필수 라이브러리: pandas, scikit-learn, requests, tqdm

데이터 구조: 각 문서는 course(코스명), section(섹션), question(질문), text(답변 내용)로 구성된 JSON 형태입니다.


3. 텍스트 검색 구현 (Text Search)
텍스트를 컴퓨터가 이해할 수 있는 숫자(벡터)로 변환하는 과정이 핵심입니다.

Bag of Words & CountVectorizer: 문장에서 단어의 순서는 무시하고 어떤 단어가 몇 번 나왔는지만 기록합니다.

TF-IDF (Term Frequency-Inverse Document Frequency):

TF: 특정 문서에 많이 나오는 단어에 가중치를 줍니다.

IDF: 모든 문서에 흔하게 나오는 단어(예: 'a', 'the', 'is')는 중요도를 낮추고, 희귀한 단어(예: 'Docker', 'YAML')에 더 높은 가중치를 줍니다.

유사도 계산 (Cosine Similarity): 쿼리(질문) 벡터와 문서 벡터 사이의 각도를 계산하여 얼마나 유사한지 점수를 매깁니다. 이 과정은 행렬 곱(Dot Product)을 통해 매우 빠르게 계산됩니다.

고급 검색 기능
필터링(Filtering): 특정 코스(예: DE Zoomcamp)의 데이터만 검색 결과에 나오도록 마스킹 처리를 합니다.

가중치 부여(Boosting): 질문(question) 필드에 키워드가 있는 것이 본문(text)에 있는 것보다 더 중요할 수 있습니다. 이때 질문 필드 점수에 3배의 가중치를 주는 등의 처리를 합니다.


4. 벡터 검색과 임베딩 (Embeddings & Vector Search)
키워드가 정확히 일치하지 않아도 의미상 가까운 문서를 찾는 방법입니다.

SVD (특이값 분해) & NMF (비음수 행렬 분해): 수천 개의 단어 열을 가진 거대한 행렬을 16개 정도의 핵심 '토픽'으로 압축합니다. 이 과정을 통해 '동의어'들이 비슷한 공간에 모이게 됩니다. (Dense Embedding)

BERT (Transformer 기반 모델): 단순 단어 묶음을 넘어 단어의 순서와 문맥을 이해합니다. Hugging Face의 모델을 사용하여 문장을 고차원 벡터로 변환하며, 이는 훨씬 정교한 검색을 가능하게 합니다.


5. 실무적 관점과 도구들
우리가 만든 엔진은 모든 문서를 메모리에 올리고 일일이 계산하지만, 실제 수백만 건의 데이터를 다룰 때는 다른 기술이 필요합니다.

Inverted Index (역색인): 키워드별로 해당 키워드가 포함된 문서 목록을 미리 만들어두는 방식입니다. (Elasticsearch의 핵심 원리)

LSH (Locality Sensitive Hashing): 벡터 검색 속도를 높이기 위해 비슷한 벡터들을 미리 같은 '바구니(Bin)'에 담아두는 기법입니다.

평가 지표: 어떤 임베딩이 좋은지 판단하기 위해 Recall@5, MRR, nDCG 같은 지표를 사용하여 검색 품질을 수치화합니다.


6. 결론
지금까지 우리가 실습한 이 모든 로직(TF-IDF, Boosting, Filtering, Ranking)을 하나의 파이썬 클래스로 모은 것이 바로 **minsearch.py**입니다. 이 클래스는 이번 코스 전체에서 우리의 '토이 엔진'으로 활약할 것이며, 나중에 우리는 이 부분을 Elasticsearch로 교체하는 법도 배울 것입니다.

2. Basics of Text Search
2. 텍스트 검색의 기초

Information Retrieval 
정보 검색 - 사용자 질의에 따라 대규모 데이터 세트에서 관련 정보를 추출하는 과정.

Vector Spaces
벡터 공간 - 텍스트를 벡터(공간상의 점)로 변환하여 정량적 비교를 가능하게 하는 수학적 표현 방식입니다.

Bag of Words
Bag of Words 는 문법과 단어 순서는 무시하되 단어의 다중성은 유지하는, 각 문서를 단어들의 모음으로 취급하는 간단한 텍스트 표현 모델입니다.

TF-IDF (Term Frequency-Inverse Document Frequency) 
특정 단어가 문서 집합(Collection) 또는 코퍼스(Corpus, 말뭉치) 내에서 특정 문서에 대해 얼마나 중요한지를 평가하는 데 사용되는 통계적 지표입니다. 이 값은 특정 문서 내에서 단어가 등장하는 횟수에 비례하여 증가하지만, 코퍼스 전체에서 해당 단어가 나타나는 빈도에 따라 그 중요도가 상쇄되어 조정됩니다.


**코퍼스(Corpus)**는 언어학이나 데이터 분석 분야에서 쓰이는 용어로, 우리말로 하면 **'말뭉치'**라고 부릅니다.

쉽게 설명하자면 다음과 같습니다:

1. 코퍼스의 정의
데이터의 집합체: 특정 목적을 가지고 수집된 텍스트 데이터의 거대한 덩어리를 의미합니다.

분석의 단위: TF-IDF 계산에서 '문서(Document)' 하나하나가 모여 전체를 이룬 전체 문서 꾸러미가 바로 코퍼스입니다.

2. TF-IDF 맥락에서의 의미
TF-IDF의 수식을 보면 코퍼스의 역할을 더 쉽게 이해할 수 있습니다.

TF (Term Frequency): '한 문서' 안에서 단어가 얼마나 자주 나오는가?

IDF (Inverse Document Frequency): '코퍼스 전체'(모든 문서들)에서 이 단어가 얼마나 흔한가?

예시:
여러분이 1,000개의 뉴스 기사를 분석한다면, 이 1,000개의 기사 전체가 **'코퍼스'**가 됩니다.

'대통령'이라는 단어가 1번 기사에도 있고, 500번 기사에도 있고, 1,000번 기사에도 있다면(코퍼스 전체에서 흔하다면), 이 단어는 해당 기사만의 핵심 키워드가 아닐 확률이 높다고 판단하여 점수를 낮춥니다.

3. 워크숍 데이터에서의 코퍼스
우리가 지금 다루고 있는 워크숍 코드를 기준으로 보면:

문서(Document): FAQ 리스트에 들어있는 개별 질문-답변 항목 하나하나입니다.

코퍼스(Corpus): 우리가 docs_url에서 내려받은 **전체 FAQ 데이터셋(df['text'] 전체)**이 됩니다.

결론적으로, 코퍼스는 "비교 대상이 되는 전체 텍스트 데이터의 집합"이라고 이해하시면 정확합니다. 이제 코퍼스 전체에서 흔한 단어를 걸러내는 IDF의 원리가 조금 더 명확해지셨나요?





[개념 이해를 돕는 상세 설명]
TF-IDF는 단순히 단어가 많이 나왔다고 해서 중요하다고 판단하지 않고, **'희소성'**을 함께 고려합니다.

TF (Term Frequency, 단어 빈도):

특정 문서 내에서 해당 단어가 얼마나 많이 나오는지를 측정합니다.

당연히 한 문서에서 자주 등장하는 단어는 그 문서의 주제와 관련이 깊을 확률이 높습니다.

IDF (Inverse Document Frequency, 역문서 빈도):

단어의 '흔한 정도'를 측정하여 가중치를 조절하는 역할을 합니다.

예를 들어 '이', '그', '것' 같은 단어는 모든 문서에서 아주 많이 등장하지만, 정작 문서의 주제를 파악하는 데는 큰 도움이 되지 않습니다.

따라서 전체 코퍼스 내 많은 문서에서 공통적으로 발견되는 단어일수록 중요도를 낮게(상쇄) 책정합니다.

결론
결국 TF-IDF 점수가 높다는 것은 **"다른 문서들에서는 잘 안 나오는데, 이 문서에서만 유독 자주 등장하는 단어"**라는 뜻이며, 이는 곧 해당 단어가 그 문서의 가장 핵심적인 키워드임을 의미합니다.

3-2. TF-IDF 벡터화 (Vectorization)

컴퓨터는 텍스트를 직접 이해하지 못하므로 숫자로 이루어진 행렬(Vector)로 바꿔야 합니다. 
즉, 컴퓨터는 "Course starts on Jan"이라는 말을 이해하지 못합니다. 그래서 이를 **좌표 평면 위의 점(Vector)**으로 변환해야 수학적인 비교가 가능해집니다.
여기서는 단어의 중요도를 반영하는 TF-IDF 방식을 사용합니다.

먼저, text 필드를 대상으로 벡터화 작업을 수행합니다.

컴퓨터가 이해할 수 있도록 텍스트를 숫자의 나열(벡터)로 변환합니다.

1) 단어 모음 (Bag of Words)
문법과 순서는 다 버리고, 오직 어떤 단어가 몇 번 나왔나만 셉니다. 가방(Bag) 속에 단어들을 마구 집어넣고 개수만 확인하는 것과 같습니다.

Python
from sklearn.feature_extraction.text import CountVectorizer

# 실험용 데이터: 검색 엔진이 읽어야 할 '문서'들입니다.
docs_example = [
    "Course starts on 15th Jan 2024",
    "Prerequisites listed on GitHub",
    "Submit homeworks after start date",
    "Registration not required for participation",
    "Setup Google Cloud and Python before course"
]
(노트북의 것과는 다름)

# 1. CountVectorizer 객체 생성
# stop_words='english': 'on', 'and', 'the' 같이 의미 없는 단어들을 자동으로 제거합니다.
cv = CountVectorizer(stop_words='english')

# 2. fit_transform: 단어 사전을 만들고(fit), 문서를 숫자 행렬로 변환(transform)합니다.
X = cv.fit_transform(docs_example)

# 3. 생성된 단어 사전(컬럼명) 확인
names = cv.get_feature_names_out()


# 4. 시각화: 행렬(Sparse Matrix)을 우리가 보기 편하게 표(DataFrame)로 바꿉니다.
# .T는 행과 열을 바꿔서(Transpose) 단어별 빈도를 세로로 보기 위함입니다.
df_docs = pd.DataFrame(X.toarray(), columns=names).T
df_docs
왜 하나요? 가장 기본적인 형태의 수치화입니다. 특정 단어가 많이 나온 문서가 관련성이 높을 것이라는 가정에서 시작합니다.


2) TF-IDF 적용: 단어의 가치 평가
단순 빈도수(Count)의 치명적인 약점은 모든 문서에 흔하게 나오는 단어(예: 'course')에 너무 높은 점수를 준다는 것입니다. TF-IDF는 '희귀하고 중요한 단어'에 더 높은 점수를 줍니다.

Python

# 2. 데이터 학습 및 변환 (위와 동일한 절차)
X = cv.fit_transform(docs_example)

# 이거 설명 누락
names = cv.get_feature_names_out()

# 3. 결과 확인 (소수점 둘째 자리까지 반올림)
# 이제 단순 정수가 아니라 0~1 사이의 '중요도 가중치'가 부여된 것을 볼 수 있습니다.
df_docs = pd.DataFrame(X.toarray(), columns=names).T
df_docs.round(2)

GEM> 이 코드는 텍스트 데이터를 숫자로 바꾸는 '기계'를 설정하는 핵심 설정값입니다. **TfidfVectorizer**라는 도구를 꺼내면서 두 가지 중요한 옵션(옵션은 '하이퍼파라미터'라고 부릅니다)을 준 것입니다.


**TfidfVectorizer**는 Scikit-learn 라이브러리에서 제공하는 도구로, 텍스트 데이터를 컴퓨터가 계산할 수 있는 **'의미 있는 숫자(행렬)'**로 변환해주는 핵심 함수입니다.

초심자가 이 함수의 정체를 완벽히 파악할 수 있도록, 세 가지 관점에서 뜯어보겠습니다.

1. 이름의 유래 (무슨 뜻인가요?)
이 함수는 두 가지 수학적 개념을 합친 것입니다.

TF (Term Frequency, 단어 빈도): 특정 문서에 단어가 얼마나 자주 나오는가? (많이 나오면 중요함)

IDF (Inverse Document Frequency, 역문서 빈도): 모든 문서에서 이 단어가 얼마나 흔한가? (너무 흔하면 안 중요함 - 예: 'the', 'is')

Vectorizer: 이 계산 결과를 바탕으로 텍스트를 방향을 가진 화살표(벡터, 숫자 배열)로 바꾼다는 뜻입니다.

2. 하는 일 (어떤 과정을 거치나요?)
TfidfVectorizer를 실행하면 내부적으로 다음과 같은 **'공장 라인'**이 돌아갑니다.

토큰화 (Tokenization): 문장을 단어 단위로 쪼갭니다.

어휘 사전 구축 (Vocabulary Building): 전체 데이터에 나온 단어들을 모아 0번, 1번, 2번... 식으로 번호표를 매깁니다. (fit 단계)

빈도 계산: 각 문서마다 단어가 몇 번 쓰였는지 셉니다.

가중치 조절: 모든 문서에 다 나오는 흔한 단어는 점수를 깎고, 특정 문서에만 나오는 귀한 단어는 점수를 높입니다.

변환 (Transformation): 최종 점수를 숫자의 나열(배열)로 출력합니다. (transform 단계)


3. 주요 설정값 (우리가 코드에서 쓴 옵션들)
함수를 호출할 때 괄호 안에 넣는 값들이 이 공장의 설정값을 결정합니다.

설정(Parameter)	의미	초심자용 해석

stop_words='english'	불용어 처리	"the, a, is 같은 찌꺼기 단어는 계산에서 빼라."

min_df=3	최소 빈도 제한	"최소 3개 문서에는 나온 단어만 써라. (오타나 듣보잡 제거)"

max_df=0.5	최대 빈도 제한	"너무 흔해서 50% 이상의 문서에 나오는 단어도 빼라."

ngram_range=(1, 2)	단어 묶음 단위	"단어 1개씩뿐만 아니라, 2개 묶음(예: 'Data Science')도 하나의 단어로 취급해라."

💡 왜 이 함수를 쓰나요?
우리가 검색 엔진을 만들 때 단순히 단어가 포함되었는지만 보면, "the"라는 단어가 포함된 문서를 가장 먼저 보여주는 실수를 범하게 됩니다. 하지만 TfidfVectorizer를 쓰면 **"질문하신 단어가 이 문서에서 특히 중요하게 다뤄지고 있습니다"**라는 것을 수학적으로 증명해서 보여줄 수 있기 때문에 사용합니다.









초심자 관점에서 이 옵션들이 왜 필요한지 하나씩 뜯어보겠습니다.

1. stop_words='english' (불용어 제거)
해석: "영어에서 의미 없는 단어들은 무시해!"라는 뜻입니다.

이유: 영어 문장에는 the, is, at, which, on 같이 문법적으로는 중요하지만, 정작 내용을 파악하는 데는 전혀 도움이 안 되는 단어들이 아주 많습니다.

효과: * 이런 단어들을 사전에 포함하면 데이터의 크기만 커지고 계산 속도가 느려집니다.

불용어를 제거함으로써 python, course, homework 같은 진짜 중요한 키워드에만 컴퓨터가 집중하게 만듭니다.

2. min_df=3 (최소 문서 빈도 제한)
해석: "전체 문서들 중에서 최소한 3개 이상의 문서에서 나타난 단어만 사전에 넣어!"라는 뜻입니다. (min_df는 Minimum Document Frequency의 약자입니다.)

이유: * 오타 및 노이즈 제거: 어떤 문서에만 딱 한 번 등장하는 단어는 오타일 수도 있고, 아주 특수한 고유명사라 검색어로서의 가치가 떨어질 수 있습니다.

일반화: 너무 희귀한 단어까지 다 학습하면, 우리 검색 엔진이 너무 예민해져서 오히려 보편적인 질문을 잘 처리하지 못하게 될 수 있습니다.

효과: * 전체 단어 사전의 개수를 확 줄여줍니다. (메모리 절약 및 성능 향상)

최소 3번 이상 검증된 단어들만 사용하므로 검색 시스템이 더 안정적으로 변합니다.

이 설정이 끝나고 나면 이제 **fit_transform**을 통해 진짜 '알짜배기 사전'이 만들어지게 됩니다. 이 옵션들이 결과에 어떤 영향을 주는지 이해가 되셨나요?




1. stop_words='english'의 의미 (보충)
이미 설명해 드린 대로 의미 없는 단어를 거르는 필터인데, 여기서 'english'라고 지정하면 scikit-learn 라이브러리가 내부적으로 정의해둔 영어 불용어 목록(약 300여 개)을 자동으로 불러와서 적용합니다. 우리가 일일이 "the, a, is..."를 타이핑할 필요가 없게 해주는 편리한 설정이죠.

2. 코드 한 줄씩 뜯어보기
X = cv.fit_transform(df[field])
해석: "특정 필드(예: 질문들만 모아둔 열)를 가져와서, 단어 사전도 만들고(fit) 동시에 **숫자 행렬로 변환(transform)**해서 X에 담아라!"

왜 하나요?: 위에서 설정한 min_df=3이나 불용어 제거 규칙을 적용해, 해당 필드에 최적화된 **'숫자 점수판(X)'**을 실제로 생성하는 순간입니다.

transformers[field] = cv
해석: "이 필드(field)의 단어들을 숫자로 바꿀 때 썼던 **'학습된 도구(cv)'**를 transformers라는 이름의 창고에 저장해둬!"

왜 하나요?: 나중에 사용자가 질문(Query)을 던졌을 때, **아까 그 필드와 똑같은 기준(색인 번호)**으로 질문을 변환해야 하기 때문입니다. (우리가 앞서 배운 transform을 다시 쓰기 위해 도구를 보관하는 것입니다.)

matrices[field] = X
해석: "방금 만들어진 **'숫자 점수판(X)'**도 matrices라는 창고에 저장해둬!"

왜 하나요?: 나중에 사용자의 질문 벡터가 들어오면, 이 점수판이랑 내적(Dot Product) 연산을 해서 유사도를 계산해야 하니까요.

IDF (Inverse Document Frequency, 역문서 빈도): 모든 문서에서 이 단어가 얼마나 흔한가? (너무 흔하면 안 중요함 - 예: 'the', 'is')
가중치 조절: 모든 문서에 다 나오는 흔한 단어는 점수를 깎고, 특정 문서에만 나오는 귀한 단어는 점수를 높입니다."


최소 3개 이상이라는데 이건 idf를 위반하지만 tf는 충족해보여. 그럼 이 함수는 뭘의미해

GEM> 결론부터 말씀드리면, min_df=3은 TF나 IDF의 수식을 계산하기 **'전'**에 수행하는 **'입장 컷(사전 필터링)'**입니다.

이 함수가 무엇을 의미하는지, 왜 모순처럼 보이는지 초심자 관점에서 명쾌하게 풀어드릴게요.

1. min_df=3은 '계산'이 아니라 '자격 심사'입니다.
TF-IDF 계산을 시작하기 전에, 컴퓨터는 전체 문서(코퍼스)를 훑으며 단어들의 명단을 만듭니다. 이때 min_df=3은 이렇게 말하는 것과 같습니다.

"얘들아, 오늘 TF-IDF 점수 잔치 벌일 건데, 최소한 3개 이상의 문서에 얼굴을 비춘 단어들만 입장 가능하다! 딱 한두 번 나오고 말 애들은 아예 명단(Vocabulary)에서 빼버려!"

즉, TF-IDF 점수를 매길 가치조차 없는 '노이즈'를 제거하는 단계입니다.

2. 왜 IDF를 위반하는 것처럼 보일까요?
원래 IDF의 논리: "적은 문서에 나타날수록 귀한 단어니까 점수를 높게 주자!"

min_df=3의 논리: "1~2개 문서에만 나타나는 단어는 너무 희귀해서 오히려 믿을 수 없으니 버리자!"

여기서 발생하는 차이: IDF는 **'희귀함 = 중요함'**으로 보지만, 실무(데이터 엔지니어링)에서는 **'너무 희귀함 = 오타, 혹은 쓸모없는 특수문자'**일 확률이 높다고 봅니다.

예를 들어, 어떤 문서에 실수로 적힌 asdf123이라는 오타는 딱 한 번 등장하겠죠? IDF 논리대로라면 이 단어는 '지구상에 단 하나뿐인 초특급 귀중 단어'가 되어 검색 결과 1위를 차지하게 됩니다. 이런 대참사를 막기 위해 최소한의 검증(3개 문서 등장)을 거친 단어들 중에서만 IDF의 '희귀성'을 따지는 것입니다.

3. 결국 이 함수(TfidfVectorizer)가 의미하는 것
이 함수는 결국 **"안전하게 검증된 범위 내에서 최대한의 변별력을 찾겠다"**는 뜻입니다.

필터링 (min_df): 너무 희귀해서 신뢰할 수 없는 쓰레기 데이터(오타 등)를 1차로 걸러낸다.

TF 점수: 살아남은 단어들 중, 특정 문서에서 많이 쓰였다면 일단 점수를 준다.

IDF 점수: 하지만 그 단어가 (3개 이상이긴 해도) 모든 문서에 너무 흔하게 깔려 있다면 다시 점수를 깎는다.

💡 요약하자면
TF: "이 문서에서 주인공인가?"

IDF: "다른 문서에서도 흔한 조연인가?"

min_df: "배우 명단에 이름을 올릴 최소한의 출연 경력이 있는가?"

이제 min_df=3이 왜 IDF의 논리를 보완하는 '안전장치' 역할을 하는지 이해가 되셨나요? 질문하신 것처럼 TF의 논리(자주 나옴)를 어느 정도 보장하면서, IDF가 가질 수 있는 '오타에 취약한 점'을 보완하는 아주 실무적인 설정입니다.

3-5. 가중치(Boosting) 및 최종 클래스화
사용자가 질문한 단어가 '답변' 보다는 '질문' 필드에 들어있을 때 더 정답일 확률이 높겠죠? 특정 필드에 힘을 실어주는 부스팅(Boosting) 기능을 포함해 클래스로 묶습니다.

Python
class TextSearch:
    def __init__(self, text_fields):
        self.text_fields = text_fields # 검색 대상 필드 (예: ['question', 'text'])
        self.matrices = {}            # 학습된 행렬 저장
        self.vectorizers = {}         # 학습된 벡터라이저 저장

    def fit(self, records, vectorizer_params={}):
        """데이터를 읽어서 필드별로 TF-IDF 학습을 수행합니다."""
        self.df = pd.DataFrame(records)
        for f in self.text_fields:
            cv = TfidfVectorizer(**vectorizer_params)
            X = cv.fit_transform(self.df[f])
            self.matrices[f] = X
            self.vectorizers[f] = cv

    def search(self, query, n_results=10, boost={}, filters={}):
        """질문을 입력받아 가중치와 필터를 적용해 검색 결과를 반환합니다."""
        # 1. 문서 개수만큼의 빈 점수판 생성
        score = np.zeros(len(self.df))
        
        # 2. 각 필드별 점수 합산 (가중치 적용)
        for f in self.text_fields:
            b = boost.get(f, 1.0) # 설정된 가중치가 없으면 기본 1.0
            q = self.vectorizers[f].transform([query])
            s = cosine_similarity(self.matrices[f], q).flatten()
            score = score + (b * s) # 가중치를 곱해 점수에 누적
        
        # 3. 필터링 적용: 특정 조건(예: 코스명)에 맞지 않으면 점수를 0으로 만듦
        for field, value in filters.items():
            mask = (self.df[field] == value).values
            score = score * mask

        # 4. 상위 n개의 결과 반환
        idx = np.argsort(-score)[:n_results]
        return self.df.iloc[idx].to_dict(orient='records')
