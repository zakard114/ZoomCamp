1.1 LLM 및 RAG 입문 (Introduction to LLM and RAG)
이번 단원에서는 LLM(거대 언어 모델)의 실무적 활용에 초점을 맞추며, 특히 RAG(Retrieval-Augmented Generation, 검색 증강 생성)를 집중적으로 다룹니다. 우리는 코스 전반에 걸쳐 수강생들이 자주 묻는 질문(FAQ) 데이터를 활용하여 질문 답변(Q&A) 시스템을 구축할 것입니다. 여기서는 LLM의 내부 이론을 깊게 파고들기보다, 이를 어떻게 효과적으로 활용할 수 있는지에 대한 실무적인 방법을 배웁니다.

해결하려는 문제 (The Problem)
DataTalks.Club 커뮤니티에는 여러 코스가 개설되어 있으며, 각 코스마다 수강생들이 자주 묻는 질문을 모아둔 FAQ 문서가 있습니다. 이 문서들은 매우 유용하지만, 분량이 수백 페이지에 달해 학생들이 원하는 정보를 신속하게 찾아내기가 어렵습니다.

우리가 만들고자 하는 시스템은 수강생이 질문을 입력하면, 시스템이 FAQ 문서에서 가장 연관성 높은 내용을 찾아내고, 이를 바탕으로 정확한 답변을 생성하여 사용자에게 전달하는 구조입니다.

LLM의 이해 (Understanding LLMs)
LLM은 Large Language Model(거대 언어 모델)의 약자입니다. 기본적으로 언어 모델이란, 지금까지 입력된 텍스트를 바탕으로 다음에 올 가장 논리적인 단어(또는 토큰)를 예측하는 시스템입니다. 스마트폰의 문자 자동 완성 기능이 대표적인 예시입니다.

기존의 작은 언어 모델들과 달리, 거대 언어 모델(LLM)은 수십억 개의 파라미터(매개변수)를 가지고 있으며 방대한 양의 데이터로 학습되었습니다. 그 결과, 단순히 다음 단어를 예측하는 것을 넘어 마치 인간과 대화하는 듯한 고도의 지능적인 답변을 제공할 수 있습니다.

이번 코스에서 우리는 LLM의 내부 구조(예: 트랜스포머 신경망 구조)를 상세히 분석하지 않고 하나의 '블랙박스(Black Box)'로 취급합니다. 즉, 프롬프트(Prompt)라는 텍스트 입력을 주면 의미 있는 답변(Answer)을 출력하는 똑똑한 도구로 활용할 것입니다.


RAG란 무엇인가? (Exploring RAG)
RAG는 Retrieval-Augmented Generation(검색 증강 생성)의 약자입니다. 이는 LLM이 답변을 생성(Generation)할 때, 외부 지식 베이스에서 관련 정보를 검색(Retrieval)하여 그 내용을 바탕으로 답변을 보강(Augmented)하는 기술입니다.

일반적인 LLM은 자신이 학습한 데이터만을 바탕으로 대답합니다. 예를 들어 "연어 요리법" 같은 일반적인 질문에는 잘 답변하지만, "이 코스에 지금 등록해도 늦지 않나요?"와 같이 학습 데이터에 없는 특정 커뮤니티나 최신 정보에 대해서는 알지 못하며, 잘못된 정보를 지어내는 환각(Hallucination) 현상이 발생할 수 있습니다.

RAG는 이러한 한계를 다음과 같은 과정으로 해결합니다:

사용자 질문: 사용자가 시스템에 질문을 던집니다.

검색(Retrieval): 질문을 지식 베이스(예: FAQ 데이터베이스)로 보내 연관된 문서들을 찾아냅니다.

컨텍스트 포함 프롬프트 구성: 검색된 문서들을 '참고 자료(Context)'로 삼아 사용자 질문과 함께 하나의 프롬프트로 결합합니다.

생성(Generation): LLM은 제공된 참고 자료를 바탕으로 정확하고 검증된 답변을 생성하여 사용자에게 반환합니다.

이번 모듈에서는 먼저 아주 단순한 형태의 자체 제작 검색 엔진으로 시작하여, 이후 이를 Elasticsearch로 교체하고, 나아가 벡터 서치(Vector Search)와 에이전트 기능(Agentic functions)까지 확장 적용해 볼 것입니다. 또한 OpenAI API뿐만 아니라 다양한 오픈소스 LLM을 연동하는 방법도 함께 다루게 됩니다.

## 주피터 노트북 실행 및 테스트 (Running Jupyter Notebook)

1. 터미널에 `jupyter notebook`을 입력하여 서버를 실행합니다.
2. GitHub Codespaces를 사용하는 경우, 8888 포트를 자동으로 감지하여 로컬 머신으로 포워딩해 줍니다.
3. 브라우저를 열고 `localhost:8888`로 접속합니다. 로그인 토큰을 요구하면 터미널에 출력된 토큰 값을 복사하여 붙여넣습니다.
4. 새로운 `Python 3` 노트북을 생성하고 아래 코드를 입력하여 환경 변수에 등록된 API 키가 정상적으로 인식되는지, LLM 호출이 잘 되는지 테스트합니다.

```python
import os
from openai import OpenAI

# 클라이언트를 초기화하면 환경 변수의 OPENAI_API_KEY를 자동으로 읽어옵니다.
client = OpenAI()

# 간단한 챗 완성(Chat Completion) 요청 테스트
# 파일명: 02-environment.md 관련 실습 코드

import os  # 운영체제(OS) 환경 변수에 접근하기 위해 라이브러리를 가져옵니다.
from openai import OpenAI  # OpenAI API와 통신할 핵심 도구를 가져옵니다.

client = OpenAI()  # 환경 변수에 등록된 API 키를 자동으로 읽어와 연결 창구를 개설합니다.

response = client.chat.completions.create(  # OpenAI 시스템에 새로운 대화 생성을 요청하고 결과를 response에 저장합니다.
    model="gpt-4o",  # 답변을 생성할 인공지능 두뇌(모델)로 gpt-4o를 지정합니다.
    messages=[  # 대화 내용을 담는 리스트입니다.
        {
            "role": "user",  # 말하는 사람의 역할이 '일반 사용자'임을 지정합니다.
            "content": "Is it too late to join the course?",  # 인공지능에게 던질 실제 질문 내용입니다.
        }
    ],
)

print(
    response.choices[0].message.content
)  # 받은 답변 뭉치 중 첫 번째 후보(choices[0])의 텍스트 알맹이(content)만 화면에 출력합니다.


참고: 아직 시스템에 코스 관련 참고 자료(Context)를 주지 않았기 때문에, LLM은 어떤 코스를 말하는지 알 수 없다는 일반적인 답변을 탈 것입니다. 이것이 정상적인 결과입니다.
