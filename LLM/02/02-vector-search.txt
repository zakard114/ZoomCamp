Chapter 1: 벡터 검색이란 무엇이며 어떻게 작동하는가? (0:00 ~ 3:28)

[스크립트 번역]
"안녕하세요! 이 코스에 참여해 주셔서 정말 반갑습니다. 저는 Qdrant의 개발자 에드보킷(Developer Advocate) 제니(Jenny)입니다. 오늘은 Qdrant를 이용한 벡터 검색의 간단한 예제를 함께 살펴볼 거예요.

벡터 검색이 '시맨틱 유사성(Semantic Similarity, 의미적 유사성)'을 통해 어떻게 작동하는지 시각적으로 설명해 드리고, Qdrant로 이를 어떻게 구현하는지 보여드릴게요. 오늘 저는 파이썬으로 작성된 간단한 주피터 노트북을 사용할 겁니다. 터미널은 딱 두 개의 명령어를 실행할 때만 쓸 거고요, 제 예술 실력은 좀 부족하지만 'Open Board'에 직접 그린 그림으로도 설명해 드릴게요. 비록 완벽하진 않아도 시각적인 설명이 이해를 돕는 가장 좋은 방법이라고 믿거든요.

여러분은 이미 벡터 검색이 무엇인지 어느 정도 알고 계시겠지만, 다시 한번 짚어보겠습니다. 반복은 언제나 이해에 도움이 되니까요.

여러분은 이미 전통적인 '키워드 검색(Keyword Search)'에 대해 알고 계실 겁니다. 예를 들어, 여러분이 '방망이(Bat)'를 검색한다고 해봅시다. 그게 과일박쥐(동물 Bat)를 의미할 수도 있겠죠. 전통적인 텍스트 기반 키워드 검색 방식에서는 쿼리와 문서 사이의 '단어'가 일치해야 합니다. 그래서 '동굴 속의 방망이(Bat in a cave)' 같은 문서를 찾아내죠. 즉, 키워드가 물리적으로 일치해야 검색이 됩니다.

하지만 '벡터 검색(Vector Search)'은 범위가 훨씬 넓습니다. 검색에 새로운 가능성을 열어주죠. 예를 들어, 여러분이 박쥐 그림(제가 그린 이 그림이 박쥐 같아 보인다면 말이죠!)을 찾고 싶다고 합시다. 벡터 검색은 이 쿼리와 이미지, 혹은 박쥐가 나오는 영상, 심지어 박쥐의 찍찍거리는 소리까지도 매칭할 수 있습니다.

게다가 텍스트만 다룰 때도 벡터 검색은 뛰어납니다. 서로 다른 단어로 표현되었지만 의미가 같은(동의어) 두 가지 아이디어를 연결할 수 있어요. 예를 들어 '날아다니는 쥐(Flying mouse)'라고 검색해도, 벡터 검색은 이것이 '박쥐(Bat)'를 묘사하는 방식이라는 것을 이해하고 두 텍스트를 매칭합니다. 왜냐하면 벡터 검색은 '의미의 수준(Semantics Level)'에서 작동하기 때문입니다.

텍스트를 직접 비교하는 키워드 방식과 달리, 벡터 검색에서는 이 텍스트들을 '벡터화된 표현(Vectorized Representations)'으로 변환해서 작업합니다. 텍스트나 이미지, 영상이 숫자 형태의 벡터가 되고, 이들 사이의 유사성(가까운 정도)을 수치로 계산하는 것이죠. 이때 다양한 '유사도 메트릭(Similarity Metrics)'이 사용되는데, 이는 나중에 실습에서 자세히 다루겠습니다. 이것이 바로 벡터 검색입니다."

Step 2: 데이터셋 연구 (Study the Dataset)

실제 작동하는 벡터 검색 솔루션을 구축하기 위해서는 (그리고 일반적으로 벡터 검색이 언제, 어떻게 필요한지 이해하기 위해), 데이터셋을 연구하고 우리가 다루는 데이터의 성격과 구조를 파악하는 것이 좋습니다. 예를 들어 다음과 같습니다:

모달리티(modality) — 데이터가 텍스트, 이미지, 비디오 중 무엇입니까? 아니면 이들의 조합입니까?

세부 사항(specifics) — 만약 텍스트라면: 어떤 언어가 사용되었는지, 텍스트 조각(chunk)의 크기는 어느 정도인지, 특수 문자가 포함되어 있는지 등을 확인해야 합니다.

올바른 데이터 "스키마(schema)" (무엇을 벡터화할지, 무엇을 메타데이터로 저장할지 등)

1. 임베딩(Embedding)이란 무엇인가?
컴퓨터는 "등록 이메일은 언제 오나요?"라는 문장을 읽어도 그게 '기다림'이나 '절차'에 관한 것인지 이해하지 못합니다. 단지 텍스트(문자열) 데이터로만 인식하죠.

임베딩은 이 텍스트의 '의미'를 컴퓨터가 계산할 수 있는 '숫자들의 목록(벡터)'으로 변환하는 기술입니다.

의미의 공간화: 비슷한 의미를 가진 문장들은 숫자 공간상에서 서로 가까운 위치에 있게 됩니다.

예: "등록 확인 메일"과 "언제 수강 확정되나요?"는 단어는 다르지만, 임베딩 공간에서는 매우 가까운 좌표에 위치합니다.

고차원 벡터: 우리가 선택한 jina-embeddings-v2-small-en 모델은 문장 하나를 512개의 숫자(EMBEDDING_DIMENSIONALITY = 512)로 이루어진 하나의 점으로 표현합니다.

2. FastEmbed의 기능과 장점
노트북에서 강조하는 FastEmbed는 이 임베딩 과정을 수행하는 '엔진'입니다. 특히 Qdrant와 찰떡궁합인 최적화된 라이브러리죠.

핵심 기능:
밀집 임베딩(Dense Embedding) 생성: 텍스트를 고밀도의 숫자 벡터로 변환합니다. 우리가 오늘 실습에서 가장 주력으로 사용하는 기능입니다.

경량화 및 속도: PyTorch나 TensorFlow 같은 거대한 프레임워크 없이도 ONNX Runtime을 사용해 CPU에서도 엄청나게 빠른 속도로 숫자를 계산해냅니다.

다양한 모델 지원: 텍스트뿐만 아니라 이미지, 희소 벡터(Sparse), 다중 벡터(Multivector) 임베딩까지 지원하여 하이브리드 검색을 가능하게 합니다.

Qdrant와의 직접 통합: 텍스트를 따로 변환해서 넣을 필요 없이, Qdrant 클라이언트를 통해 텍스트를 바로 전달하면 내부에서 자동으로 임베딩을 처리해주는 편리함을 제공합니다.

한 문장 요약:
임베딩은 텍스트를 **'의미가 담긴 좌표'**로 만드는 것이고, FastEmbed는 그 좌표를 **'매우 빠르고 가볍게 계산해주는 도구'**입니다.

Step 3: FastEmbed를 사용한 임베딩 모델 선택 (Choosing the Embedding Model with FastEmbed)
이제 우리는 영어로 된 작은 텍스트 조각(강좌 관련 질문 및 답변 쌍)을 임베딩한다는 사실을 알고 있으므로, 이 데이터를 벡터로 변환하기에 적합한 임베딩 모델을 선택할 수 있습니다.

임베딩 모델 선택은 다음과 같은 여러 요인에 따라 달라집니다:

수행하려는 작업, 데이터의 모달리티(텍스트, 이미지 등) 및 데이터의 특성

검색 정확도와 리소스 사용량 사이의 절충(Trade-off) (임베딩 크기가 클수록 더 많은 저장 공간과 메모리가 필요함)

추론 비용 (특히 서드파티 API 제공업체를 사용하는 경우)

기타 요인들

임베딩 모델을 선택하는 가장 좋은 방법은 자신의 실제 데이터를 사용하여 다양한 옵션을 테스트하고 벤치마킹하는 것입니다.

이 노트북에서는 임베딩 제공자로 FastEmbed를 사용합니다.
FastEmbed는 Qdrant를 위해 특별히 설계된 최적화된 임베딩 솔루션입니다. PyTorch나 TensorFlow 같은 무거운 프레임워크 없이도 CPU 친화적이고 낮은 지연 시간(Low-latency)으로 임베딩을 생성합니다. 양자화된(Quantized) 모델 가중치와 ONNX Runtime을 사용하여, CPU 환경에서 기존의 Sentence Transformers보다 훨씬 빠르면서도 경쟁력 있는 정확도를 유지합니다.

FastEmbed가 지원하는 기능:

밀집 임베딩(Dense embeddings): 텍스트와 이미지용 (가장 일반적인 유형이며, 오늘 우리가 사용할 방식입니다)

희소 임베딩(Sparse embeddings): 예: BM25, 희소 신경망 임베딩

다중 벡터 임베딩(Multivector embeddings): 예: ColPali, ColBERT 등 후기 상호작용(Late interaction) 모델

리랭커(Rerankers)

이 모든 기능은 Qdrant에서 직접 사용할 수 있습니다. 또한 FastEmbed와 Qdrant의 통합 덕분에 텍스트나 이미지를 Qdrant 클라이언트에 직접 전달하여 임베딩을 처리할 수 있습니다. 이번 실습에서는 로컬 추론을 위해 FastEmbed를 사용할 것이므로, 기기의 리소스를 고려하여 모델을 선택해야 합니다.

size_in_GB: 0.42: 모델의 무게입니다. 약 420MB 정도


💡 왜 우리는 Jina 모델을 선택했는가?
출력 결과물 중에 jinaai/jina-embeddings-v2-small-en을 선택한 이유는 명확합니다.

입력 한도 (8192 tokens): 위 예시의 BGE 모델은 512단어만 읽지만, Jina는 무려 8,192단어까지 읽을 수 있습니다. 긴 답변도 잘리지 않고 벡터화됩니다.

편의성: 질문과 문서에 별도의 접두사(Prefix)를 붙일 필요가 없어 코드가 깔끔해집니다.

효율성: 512차원(dim)을 유지하면서도 모델 크기(size_in_GB)가 0.12GB로 매우 가벼워 로컬 CPU 환경에서 부담이 없습니다.

이제 이 "숫자 변환기(모델)"의 정체를 확실히 알았으니, 이 모델이 뽑아준 숫자들을 저장할 저장소를 만들 차례입니다.

GEM> json.dumps는 파이썬 객체(리스트, 딕셔너리 등)를 JSON 형식의 문자열(String)로 변환해주는 함수입니다. 여기서 s는 String을 의미합니다.

노트북 코드에서 사용된 방식을 바탕으로 왜 이 함수를 쓰는지, 그리고 주요 옵션들이 어떤 역할을 하는지 직관적으로 설명해 드릴게요.

1. 왜 사용하는가? (객체 → 문자열)
파이썬의 dict 객체를 그대로 print()하면 한 줄로 길게 출력되어 사람이 읽기 매우 힘듭니다. json.dumps를 사용하면 이 데이터를 구조화된 문자열로 바꾸어 예쁘게 출력하거나, 파일로 저장하거나, 네트워크를 통해 전송할 수 있는 상태로 만듭니다.

2. 주요 파라미터 설명
노트북 코드에 나온 예시를 보겠습니다.

Python
print(json.dumps(model, indent=2))
model: 변환할 대상(여기서는 모델 정보가 담긴 딕셔너리)입니다.

indent=2: 가장 중요한 옵션입니다. 들여쓰기를 2칸씩 적용하라는 뜻입니다. 이 옵션이 있어야 줄 바꿈이 정돈되어 우리가 보기 편한 "예쁜" 형태로 출력됩니다. 만약 이 옵션이 없으면 모든 데이터가 한 줄로 다닥다닥 붙어서 나옵니다.


3. json.load vs json.dump (참고)
헷갈리기 쉬운 용어들을 정리해 드릴게요.

함수		방향		결과물
json.loads()	문자열 → 객체	파이썬 딕셔너리/리스트 (메모리상 존재)
json.dumps()	객체 → 문자열	JSON 텍스트 (출력/로그 확인용)
json.load()	파일 → 객체	파일에서 데이터를 읽어와 파이썬 객체로 변환
json.dump()	객체 → 파일	파이썬 객체를 JSON 파일로 직접 저장

💡 직관적인 파라미터 설명
이 단계는 데이터를 넣기 전, "어떤 규격의 데이터를 담을 것인가"를 결정하는 매우 중요한 단계입니다.

size=EMBEDDING_DIMENSIONALITY (512):

**우리가 선택한 Jina 모델은 문장을 512개의 숫자로 변환합니다. 만약 이 그릇(컬렉션)의 크기를 512가 아닌 다른 숫자(예: 768)로 만들면, 데이터가 들어갈 때 "규격 불일치" 에러가 발생합니다. 즉, 모델이 만드는 숫자 개수와 컬렉션의 크기를 반드시 맞춰야 합니다.

client.create_collection:

Step 5: 포인트 생성, 임베딩 및 컬렉션 삽입 (Create, Embed & Insert Points)
포인트(Points)는 Qdrant 데이터의 핵심 단위입니다. 각 포인트는 다음 세 가지로 구성됩니다:

ID: 고유 식별자입니다. Qdrant는 64비트 정수와 UUID를 모두 지원합니다.

Vector: 데이터의 의미를 나타내는 임베딩(숫자 목록)입니다.

Payload (선택사항): 키-값 쌍으로 이루어진 추가 메타데이터입니다.


1. 포인트 구조 생성 (Point Structuring)
먼저 우리가 가진 데이터를 Qdrant가 이해할 수 있는 포인트 형태로 변환합니다.


Python
points = [] # 생성된 포인트들을 담을 리스트
id = 0 # 포인트마다 부여할 고유 ID (0부터 시작)

# 로드한 로우 데이터(documents_raw)를 순회하며 포인트 생성
for course in documents_raw:
    for doc in course['documents']:

        # Qdrant의 포인트 구조(PointStruct)를 정의합니다.
        point = models.PointStruct(
            id=id, # 고유 정수 ID 부여
            
            # [핵심] FastEmbed를 사용하여 로컬에서 텍스트를 즉시 임베딩합니다.
            # "jinaai/jina-embeddings-v2-small-en" 모델을 사용하여 text 필드를 벡터로 변환합니다.
            vector=models.Document(text=doc['text'], model=model_handle),
            
            # 검색 결과와 함께 출력하거나 필터링에 사용할 메타데이터를 저장합니다.
            payload={
                "text": doc['text'],      # 원문 답변 텍스트
                "section": doc['section'], # 속한 섹션 (예: General course-related questions)
                "course": course['course'] # 강좌 이름 (예: data-engineering-zoomcamp)
            }
        )
        points.append(point) # 생성된 포인트를 리스트에 추가

        id += 1 # 다음 포인트를 위해 ID 증가



2. 임베딩 및 업로드 (Embedding & Upsert)
이제 생성된 포인트들을 컬렉션에 업로드합니다.

동작 방식: 먼저 FastEmbed가 선택한 모델 파일을 다운로드합니다. (기본 경로는 임시 폴더입니다.) 그 후, 사용자의 컴퓨터(로컬)에서 직접 추론(Inference)을 수행하여 텍스트를 벡터로 바꿉니다.

마지막으로, 생성된 포인트들이 컬렉션에 삽입(Upsert)되고 벡터 인덱스가 구축됩니다.

Python

Step 6: Running a Similarity Search
단계 6: 유사도 검색 실행하기

이제 주어진 쿼리 임베딩에 대해 Qdrant에서 가장 유사한 텍스트 벡터를 찾아봅시다. 즉, 주어진 질문에 대해 가장 관련성이 높은 답변을 찾는 과정입니다.

유사도 검색 작동 원리 (How Similarity Search Works)
Qdrant는 컬렉션을 생성할 때 정의된 거리 메트릭(Distance Metric)을 사용하여, 벡터 인덱스를 기반으로 쿼리 벡터와 저장된 벡터들을 비교합니다.

가장 가깝게 일치하는 항목들이 유사도 순으로 정렬되어 반환됩니다.

벡터 인덱스는 근사 최근접 이웃(Approximate Nearest Neighbor, ANN) 검색을 위해 구축되었으며, 이를 통해 대규모 벡터 검색이 가능해집니다.

벡터 검색을 위한 벡터 인덱스 선택에 대해 더 자세히 알고 싶다면 "벡터 데이터베이스란 무엇인가" https://qdrant.tech/articles/what-is-a-vector-database/

기사를 확인하거나, 더 기술적인 심층 분석을 원하신다면 "필터링 가능한 HNSW(Hierarchical Navigable Small World)"에 관한 기사

https://qdrant.tech/articles/filtrable-hnsw/

를 확인해 보세요.

1. 왜 벡터 인덱스가 필요한가요?
단순하게 생각하면, 내가 던진 질문과 DB에 있는 모든 답변을 하나하나 다 비교해보면 됩니다. 하지만 데이터가 100만 개, 1,000만 개로 늘어나면 이 작업은 너무 오래 걸립니다.

인덱스가 없을 때: 모든 데이터와 일일이 거리를 계산함 (정확하지만 매우 느림).

인덱스가 있을 때: 데이터를 비슷한 것끼리 미리 묶어두거나 지도를 그려두어, 관련 있는 구역만 뒤짐 (압도적으로 빠름).


2. 우리가 실습 중인 Qdrant의 핵심 기술: HNSW
원문에서 언급된 HNSW(Hierarchical Navigable Small World)가 바로 이 벡터 인덱스의 대표적인 방식입니다.

계층형(Hierarchical): 마치 구글 지도에서 '국가 → 도시 → 동네' 순으로 줌인하는 것처럼, 여러 층의 지도를 만듭니다.

탐색 가능한 작은 세상(Navigable Small World): 모든 점이 연결된 게 아니라, 몇 단계의 연결만 거치면 목적지에 도달할 수 있는 '좁은 세상' 네트워크를 만듭니다.


3. ANN (Approximate Nearest Neighbor)의 관계
인덱스를 사용하면 "완벽하게 똑같은 것"보다는 "거의 확실히 제일 가까운 것"을 찾게 됩니다. 이걸 근사 최근접 이웃(ANN) 검색이라고 합니다.

100% 정확도를 조금 양보하는 대신, 수백만 개의 데이터를 0.001초 만에 검색할 수 있게 해주는 마법 같은 기술인 셈이죠.

요약하자면
벡터 인덱스는 데이터가 너무 많아서 하나하나 찾기 힘들 때, 비슷한 것끼리 길을 연결해두어 순식간에 정답 근처로 안내해주는 고속도로라고 이해하시면 됩니다.

단계 7: 필터를 사용한 유사도 검색 실행하기 (Running a Similarity Search with Filters)

우리는 메타데이터 필터를 사용하여 검색 결과를 더욱 세밀하게 다듬을 수 있습니다.

Qdrant의 독자적인 벡터 인덱스 구현 방식인 필터링 가능한 HNSW (Filterable HNSW)를 사용하면, 필터링 조건이 포함된 상태에서도 정밀하고 확장 가능한 벡터 검색이 가능합니다.

예를 들어, 데이터셋에 포함된 세 가지 코스 중 특정 코스와 관련된 질문에 대한 답변만 검색할 수 있습니다.
must 필터를 사용하면 데이터 포인트가 검색 결과에 포함되기 위해 지정된 모든 조건을 반드시 만족해야 함을 보장합니다.

Qdrant는 should, must_not, range 등 다른 필터 유형도 지원합니다. 전체 개요를 확인하려면 필터링 가이드(Filtering Guide)를 참조하세요.

효율적인 필터링을 위해서는 페이로드 필드(payload fields)의 인덱싱을 활성화해야 합니다.

def search_in_course(query, course="mlops-zoomcamp", limit=1): # 검색어와 코스 이름(기본값 mlops-zoomcamp)을 받는 함수를 정의합니다.

    results = client.query_points( # Qdrant 클라이언트를 통해 쿼리를 수행합니다.
        collection_name=collection_name, # 대상 컬렉션의 이름을 지정합니다.
        query=models.Document( # "jinaai/jina-embeddings-v2-small-en"을 사용하여 쿼리 텍스트를 로컬에서 임베딩합니다.
            text=query, # 사용자가 입력한 질문 텍스트입니다.
            model=model_handle # 앞서 정의한 Jina 모델 핸들을 사용합니다.
        ),
        query_filter=models.Filter( # 코스 이름으로 결과를 필터링합니다.
            must=[ # 아래 조건을 반드시 만족해야 합니다.
                models.FieldCondition(
                    key="course", # "course" 필드를 확인합니다.
                    match=models.MatchValue(value=course) # 입력받은 코스 이름과 정확히 일치하는지 검사합니다.
                )
            ]
        ),
        limit=limit, # 가장 유사한 상위 매치 항목의 개수를 설정합니다.
        with_payload=True # 결과와 함께 메타데이터(텍스트 내용 등)를 가져오도록 설정합니다.
    )

    return results # 검색 결과 객체를 반환합니다.

1. 왜 엉뚱한 답이 나왔을까? (유사도의 한계)
우리가 던진 질문은 "What if I submit homeworks late?"입니다. 하지만 검색된 문장은 "답변 중 가장 가까운 것을 선택하세요..."라는 내용이죠.

원인: mlops-zoomcamp 데이터 안에는 "늦은 제출"에 대한 명확한 문장이 없거나, 혹은 다른 문장에 "submit", "answer" 같은 단어들이 벡터 공간에서 질문과 더 가깝게 배치되었기 때문입니다.

벡터 검색의 특징: 벡터 검색은 단어가 100% 일치하지 않아도 가장 '비슷해 보이는' 것을 무조건 가져옵니다. 점수가 낮더라도 limit=1을 주면 그중 1등을 가져오기 때문에 이런 엉뚱한 결과가 나올 수 있습니다.

2. 원문에서의 의도 (비교를 위한 장치)
원문 필터링 단계에서 이 예시를 굳이 보여준 이유는, "필터를 걸면 검색 범위가 좁아져서 결과가 완전히 달라진다"는 것을 보여주기 위함입니다.

Step 6(필터 없을 때): 전체 데이터에서 찾으므로 data-engineering 코스의 정확한 답변("Late submissions are not allowed...")을 찾아왔습니다.

Step 7(필터 있을 때): 범위를 mlops-zoomcamp로 강제 제한했더니, 그 코스 안에는 마땅한 답이 없어서 그나마 비슷해 보이는 엉뚱한 문장을 가져온 것입니다.

3. 실습에서 확인해볼 점
이 결과가 틀렸다고 당황하실 필요 없습니다. 오히려 "필터가 확실히 작동해서 다른 코스의 정답을 배제했구나!"라고 이해하시면 완벽합니다.
