Chapter 2. 데이터프레임 로드 및 열 이름 정규화
다운로드한 CSV 파일을 판다스의 read_csv 함수로 읽어서 컴퓨터 메모리 위에 엑셀 표처럼 올려보겠습니다.

Python
# 방금 다운로드 완료된 'data.csv' 파일을 판다스의 'read_csv' 함수로 읽어 들입니다.
# 컴퓨터 메모리 위에 이 파일이 엑셀 표 형태의 '데이터프레임(DataFrame)' 객체로 변환되어 올라가며,
# 앞으로 이 표를 자유롭게 조작할 수 있도록 'df'라는 이름의 변수에 대입합니다.
df = pd.read_csv('data.csv')


데이터를 자세히 살펴보면 컬럼(열) 이름에 대소문자가 섞여 있거나 띄어쓰기가 들어가 있어서 나중에 코딩할 때 골치 아파질 수 있어요. 점(.)으로 접근할 때 에러가 나지 않도록 깔끔하게 정리해 줍니다.

Python
# 데이터프레임의 모든 열(컬럼) 이름을 일제히 소문자로 바꾸고, 이름 속 공백은 밑줄(_)로 바꿉니다.
# 기계학습 코드에서는 열 이름을 점(.)으로 접근하는 경우가 많아서, 공백이 있으면 문법 오류가 납니다.
# '.str'은 문자열 전용 메서드 묶음이고, 메서드를 연달아 붙이는 방식(체이닝)으로 한 줄에 두 가지 변환을 끝냅니다.
df.columns = df.columns.str.lower().str.replace(' ', '_')



Chapter 3. 문자열 값(Values) 정규화하기
열 이름뿐만 아니라 데이터 안의 실제 문자열 값들도 대소문자가 제각각이에요. 테스트 삼아서 제조사(make) 열을 먼저 살짝 손봐볼까요?

Python
# 'make'(제조사) 열의 각 값을 소문자로 바꾸고, 값 안의 공백도 밑줄로 바꿉니다.

# 결과를 변수에 저장하지 않았으므로 변환된 시리즈가 출력만 되고, 원본 df는 아직 바뀌지 않습니다.
df['make'].str.lower().str.replace(' ', '_')


숫자가 들어 있는 열은 건드리면 안 되기 때문에, 진짜 글자(object 타입)가 들어 있는 열들만 골라내는 작업을 해줍니다.

Python
# 데이터 타입이 'object'(문자열)인 열만 골라, 그 열 이름들의 목록을 만듭니다.
# df.dtypes는 각 열이 숫자인지 문자인지 알려 주는 시리즈이고, 조건으로 걸러 낸 뒤 .index로 열 이름만 꺼냅니다.
# 이 이름 목록을 다음 셀의 for 반복문에서 한꺼번에 정규화하려고 'strings' 변수에 담아 둡니다.
strings = list(df.dtypes[df.dtypes == 'object'].index)

# 방금 만든 문자열 열 이름 목록을 노트북에 출력해, 어떤 열이 범주형(문자)인지 눈으로 확인합니다.
strings



이제 골라낸 문자열 열들을 반복문으로 돌면서 전체 값들을 일괄적으로 정돈해 줍니다.

Python
# 앞에서 모아 둔 문자열 열 이름들을 하나씩 꺼내며 반복합니다.
# 각 열의 실제 값에 소문자 변환과 공백→밑줄 치환을 적용하고, 그 결과를 같은 열에 다시 덮어씁니다.
# 이제 제조사·모델명 같은 범주 값이 모두 일정한 형식이 되어, 나중에 비교하거나 더미 변수로 만들기 쉬워집니다.
for col in strings:
    df[col] = df[col].str.lower().str.replace(' ', '_')

열 이름(Column names) 통일: 모든 열 이름이 소문자로 바뀌고 공백이 밑줄(_)로 치환되어, 나중에 코딩할 때 df.engine_hp처럼 점(.)을 이용해 오류 없이 편리하게 접근할 수 있게 되었습니다.

나> 위에서 objects 는 문자열이라며? 근데 float64, int64는 아닌거 아냐?

GEM> 맞습니다! 아주 예리한 지적이십니다. 판다스(Pandas)와 파이썬 판정 방식 때문에 헷갈리기 쉬운 부분인데요.

int64 / float64 타입: 명백한 숫자(정수와 실수) 전용 그릇입니다. 연산이 가능하도록 철저하게 숫자로 분류된 데이터들입니다.

로그 변환(np.log1p) 적용하기

모델이 큰 숫자를 더 쉽게 다루고 롱테일 분포를 정규분포(Normal Distribution, 종 모양)에 가깝게 만들기 위해 로그 변환(Log Transformation)을 적용합니다. 이때 값이 0인 데이터가 존재할 경우 에러가 발생하므로 1을 더해주는 np.log1p 함수를 사용합니다.

Python
# 넘파이의 log1p 함수에 샘플 숫자 리스트를 넣어, 로그 변환 결과를 확인합니다.
# log1p(x)는 log(x + 1)과 같아서, 값이 0이어도 로그가 터지지 않습니다(log(0)은 정의되지 않음).
# 가격처럼 스케일이 큰 숫자를 모델이 다루기 쉬운 범위로 압축하는 전처리의 맛보기입니다.
np.log1p([0, 1, 10, 1000, 100000])

//
나> 0, 1, 10, 1000, 100000의 의미

GEM> np.log1p([0, 1, 10, 1000, 100000]) 코드에서 입력된 숫자들은 로그 변환(log1p)이 실제 데이터의 값 크기에 따라 어떻게 값을 압축하고 변화시키는지 보여주기 위한 대표적인 예시(값의 예시)입니다.

여기서 각 숫자가 가진 의미와 log1p 함수가 왜 저 숫자들을 대상으로 쓰이는지 정리해 드립니다.

1. 각 숫자의 구체적 의미와 변환 결과
np.log1p(x)는 자연로그 함수인 $\ln(1 + x)$를 계산합니다. 입력된 숫자들을 대입해 보면 다음과 같이 변환됩니다.

0:

의미: 가격이나 수량이 전혀 없거나(0) 시작 지점인 상태를 의미합니다.

계산: ln(1+0)=ln(1)=0

1:

의미: 아주 저렴하거나 최소 단위를 뜻합니다. (예: 1달러)

계산: ln(1+1)=ln(2)≈0.693

10:

의미: 한 자릿수에서 두 자릿수로 넘어간 소규모 단위를 뜻합니다. (예: 10달러)

계산: ln(1+10)=ln(11)≈2.400

1000 (천):

의미: 중간 규모의 가격대를 뜻합니다. (예: 1,000달러)

계산: ln(1+1000)=ln(1001)≈6.909

100000 (십만):

의미: 앞서 언급한 슈퍼카나 고가 차량처럼 극단적으로 높은 가격대를 뜻합니다. (예: 100,000달러 이상)

계산: ln(1+100000)=ln(100001)≈11.513

2. 저 숫자들이 저 함수에 쓰인 이유 (핵심 목적)
자동차 가격 데이터에는 0원(또는 매우 저렴한 차)부터 수십만 달러가 넘는 슈퍼카까지 엄청나게 넓은 범위의 숫자가 섞여 있습니다.

원본 차이: 0과 100,000은 숫자 차이가 무려 10만 배나 납니다. 이 상태 그대로 머신러닝 모델에 넣으면 큰 숫자가 모델의 학습을 지배해 버립니다.

로그 변환 후 차이: 위에서 계산된 결과값을 보면 0은 0, 100,000은 약 11.5로 줄어듭니다. 즉, 스케일이 10만 배 차이 나던 거대한 숫자들을 0부터 11 사이의 다루기 편한 작은 범위로 촘촘하게 압축해 주는 것입니다.

또한, 입력값에 0이 포함되어 있을 때 일반적인 np.log(0)을 쓰면 수학적 오류(무한대, -inf)가 발생하지만, np.log1p는 내부적으로 1을 더해주기 때문에(1 + 0) 0 데이터가 망가지지 않고 안전하게 0으로 계산되도록 보호해 주는 실무적 이유도 담겨 있습니다.



나> 그러니까 저 숫자들을 한개도 아니고 여러개를 왜 []를 이용해 loglp 안에 집어넣는거냐고. 함수가 바보여서 어떤 숫자든 식별을 못하는거야? 그래서 일일히 저렇게 0,1,10,등등 메뉴얼로 집어넣어주는거냐고

저것은 실제 자동차 가격 데이터를 변환하기 전 단계에서, np.log1p() 함수가 입력된 숫자 크기에 따라 값을 어떻게 변환해 주는지 개발자가 눈으로 직접 테스트(확인)해 보려고 리스트([]) 형태로 한 번에 집어넣어 본 것입니다.

파이썬의 리스트([]) 기능:

파이썬에서는 대괄호 안에 여러 숫자를 넣으면(예: [0, 1, 10, ...]), 리스트라는 꾸러미(모음)가 됩니다.

np.log1p() 같은 넘파이(NumPy) 함수는 스마트해서, 이렇게 숫자가 여러 개 든 리스트를 통째로 집어넣으면 각 숫자를 알아서 하나씩 꺼내 전부 한꺼번에 계산한 뒤 결과도 리스트로 뱉어냅니다. (이를 벡터화 연산이라고 합니다.)

왜 굳이 저런 값들을 넣어봤을까? (동작 테스트):

진짜 자동차 가격 데이터를 변환하기 전에, "내가 쓰는 이 함수가 0이 들어왔을 때 에러는 안 나는지", "아주 작은 수와 엄청 큰 수(십만 단위)를 넣었을 때 결과가 각각 얼마로 이쁘게 압축되는지" 궁금해서 대표적인 샘플 숫자들만 골라서 실험해 본 것입니다.

즉, 함수가 숫자를 식별 못 해서가 아니라, "함수가 내 의도대로 숫자를 잘 축소해 주는지 샘플 테스트를 해본 것"에 가깝습니다. 실제 본 데이터 분석에서는 저렇게 일일이 안 넣고 price_logs = np.log1p(df.msrp)처럼 컬럼 전체를 한 번에 넣습니다.

2.5 선형 회귀 (Linear Regression)
지금까지 데이터를 훈련/검증/테스트 세트로 깔끔하게 쪼개고 정답(y)까지 분리해 두었습니다. 이제 이 데이터를 바탕으로 자동차 가격을 예측할 선형 회귀 모델의 기본 개념과 작동 원리를 파악합니다.

1. 선형 회귀란 무엇인가?
선형 회귀는 차량의 여러 특징(마력, 연식, 인기 등)에 각각 적절한 가중치(기울기)를 곱하고 기본값(편향)을 더해 최종 가격 숫자를 예측하는 가장 기본적인 머신러닝 알고리즘입니다.

전체 수식 형태:
g(xi) = w0 + (xi1 * w1) + (xi2 * w2) + ... + (xin * wn)

시그마 수식 형태 (간소화):
g(xi) = w0 + (j=1부터 n까지의 합) wj * xij

벡터 형태 (내적):
g(xi) = w0 + (xi의 전치행렬 * w)


# 훈련 세트의 10번째 행(iloc 기준)을 시리즈로 출력합니다.
# 이후 선형 회귀 예제에서 쓸 샘플 차량의 특성(마력, 연식 등)을 눈으로 확인합니다.
df_train.iloc[10]


2. 단일 차량 데이터로 선형 회귀 함수 구현하기
전체 데이터 행렬을 한 번에 다루기 전, 먼저 딱 한 대의 차량(예: 10번째 행의 롤스로이스) 데이터를 골라 손으로 직접 계산하듯 파이썬 코드로 구현해 봅니다.

Python
# filename: linear_regression_simple.py
# 훈련 세트의 10번째 차량 특성 중 일부를 골라 샘플 특성 벡터 xi를 만듭니다.
# (순서대로 마력, 도시 연비, 인기도를 뜻하는 세 숫자입니다.)
xi = [453, 11, 86]

# 편향(bias, 절편) w0입니다. 
# 차에 대한 아무런 정보가 없을 때 기본적으로 예상되는 기본 가격(로그 스케일)입니다.
w0 = 7.17

# 각 특성에 곱해질 가중치(weight) 리스트 w입니다.
# 앞서 만든 xi의 세 값과 각각 짝을 이루어 곱해집니다.
w = [0.01, 0.04, 0.002]

# 한 대의 차량 특성 벡터 xi를 받아 선형 회귀 예측값을 계산하는 함수를 정의합니다.
def linear_regression(xi):
    n = len(xi)
    
    # 예측값을 편향 w0에서부터 시작합니다.
    pred = w0
    
    # 특성 개수만큼 반복하며, (특성 값 * 가중치)를 더해나갑니다 (내적 연산).
    for j in range(n):
        pred = pred + w[j] * xi[j]
        
    return pred

# 함수에 샘플 차량을 넣고 로그 가격 예측값을 확인합니다.
print(linear_regression(xi))
# 출력 결과: 12.312

np.log1p()의 정확한 짝꿍(역함수)은 np.expm1()입니다.

# 출력 결과: 12.312


초보자를 위한 핵심 요약 가이드
선형 회귀의 뼈대: 회귀 모델은 결국 (기준값 + 특징값 * 가중치들의 총합)으로 이루어진 단순한 덧셈·곱셈의 조합입니다.

가중치(Weight)와 편향(Bias):

편향(w0): 차를 보지도 않고 매기는 기본 가격.

가중치(w): 마력이 높거나 인기가 많을 때 가격이 얼마나 오르고 내리는지 결정하는 중요도 계수.

스케일 원상복구 (np.expm1): 모델 학습과 예측은 다루기 편하게 로그 변환된 값으로 진행하되, 최종 결과물을 사람이 알아보기 위한 실제 가격으로 보여줄 때는 반드시 역함수인 np.expm1로 풀어주어야 합니다.

2.6 선형 회귀: 벡터 형태 (Linear Regression: Vector Form)
이전 단원에서는 한 대의 차량 가격을 구하기 위해 반복문(for)을 돌려가며 가중치를 하나씩 곱했습니다. 이번 단원에서는 이 복잡한 계산을 벡터(Vector)와 행렬(Matrix) 연산으로 깔끔하게 축약하고, 여러 대의 차량을 한꺼번에 예측하는 방법을 배웁니다.

1. 내적(Dot Product)으로 식 간소화하기
수식에서 특성과 가중치를 일일이 더하던 방식을 두 벡터의 내적(Dot Product) 기호로 바꾸면 훨씬 간결해집니다.

기존 식: g(xi) = w0 + (xi1 * w1) + (xi2 * w2) + ... + (xin * wn)

벡터 내적 형태: g(xi) = w0 + (xi의 전치행렬 * w)

이전 단원에서 만든 코드를 내적 함수(dot) 형태로 먼저 고쳐봅니다.

Python
# filename: linear_regression_vector.py
# 두 벡터 xi와 w의 내적(각 원소끼리 곱한 뒤 모두 더함)을 계산하는 함수를 정의합니다.
def dot(xi, w):
    n = len(xi)
    res = 0.0
    for j in range(n):
        res = res + xi[j] * w[j]
    return res

# 내적 함수를 이용해 선형 회귀 함수를 간결하게 다시 정의합니다.
def linear_regression(xi):
    return w0 + dot(xi, w)

w_new: 절편 w0을 가중치 리스트 맨 앞에 집어넣어 크기를 1칸 늘린 새로운 가중치 벡터

xi = [1] + xi: 특성 데이터 맨 앞에도 1을 집어넣어 짝을 맞춤

# 가중치 리스트 맨 앞에 절편 w0을 끼워 넣어 새로운 가중치 벡터 w_new를 만듭니다.

def linear_regression(xi):
    xi = [1] + xi

1. 절편항의 수학적 정체
선형 회귀의 예측 공식은 다음과 같습니다:
y = w_0 + w_1x_1 + w_2x_2 + w_3*x_3

여기서 w_0이 바로 절편(Bias)입니다. 그런데 다른 가중치들(w_1, w_2, w_3)은 각각 특성값(x_1, x_2, x_3)과 곱해지는데, w_0에는 곱해지는 특성값이 보이지 않습니다.

수학적으로 행렬 연산(X * w)을 깔끔하게 한 번에 처리하려면, w_0에도 항상 1이라는 상수 값이 곱해진다고 가정하면 됩니다. 즉, 식을 다음과 같이 바꿀 수 있습니다:
y = w_0 * 1 + w_1x_1 + w_2x_2 + w_3*x_3

2. 왜 하필 맨 왼쪽에 열로 붙이는가?
특성 행렬 X의 각 행은 차량 1대의 데이터이고, 열은 특성(마력, 연식 등)을 나타냅니다.

우리가 구하게 될 가중치 벡터 w의 첫 번째 원소를 절편 w_0으로 약속합니다.

따라서 행렬 곱셈 규칙(행 곱하기 열)에 의해, 가중치 벡터의 첫 번째 값(w_0)이 특성 행렬의 첫 번째 열과 곱해지도록 설계해야 합니다.

이 첫 번째 열에 전부 1을 넣어두면, 가중치 w_0에 1이 곱해져 결국 w_0 * 1 = w_0이 되므로, 자연스럽게 절편 값이 그대로 유지됩니다.

3. 만약 이 과정을 안 거치면 어떻게 되는가?

하지만 현실에서는 차에 아무런 정보가 없어도 기본적인 시세(기본 가격)가 존재하므로, 그 기본값을 잡아줄 절편(w_0)이 반드시 필요합니다.

1. 정규방정식의 필요성

왜 I가 게눈 감추듯 스리슬쩍 사라져?


GEM> 단위행렬(I)이 사라지는 이유 (과정 상세)
행렬 연산에서 단위행렬(I)은 숫자에서의 '1'과 같은 역할을 합니다. 어떤 행렬에 I를 곱해도 자기 자신이 나오기 때문에, 수학적으로는 생략해서 표기합니다.

1. 초기 방정식:
X * w = y

2. 양변에 X의 역행렬(X^-1)을 왼쪽에서 곱합니다:
(X^-1 * X) * w = X^-1 * y

3. 역행렬과 원래 행렬을 곱하면 단위행렬(I)이 됩니다:
(X^-1 * X) 부분은 I가 됩니다.
I * w = X^-1 * y

4. I * w 는 w와 같으므로, 결과적으로 I가 사라진 것처럼 정리됩니다:
w = X^-1 * y

왜 스르르 사라지는가?

숫자 계산에서 1 * w = w라고 쓰는 것과 똑같습니다.

I * w = w 이기 때문에, 굳이 I를 계속 표기하지 않고 결과값인 w만 깔끔하게 남겨두는 것입니다.

즉, 생략된 것이 아니라 '단위행렬의 곱은 자기 자신'이라는 정의에 따라 w로 변환된 것입니다.


나> X^-1 * X  가 X/X로 1이기 때문에 I로 치환해주는거냐?

숫자 연산과 행렬 연산을 비교하면 왜 그렇게 치환하는지 이해하기 쉽습니다.

1. 숫자의 경우 (나눗셈)
숫자에서는 나눗셈이 가능하죠.

A * w = y

양변을 A로 나눕니다.

(A / A) * w = y / A

1 * w = y / A  (여기서 1이 바로 단위행렬 I의 역할을 합니다.)

w = y / A

2. 행렬의 경우 (나눗셈이 없음)
행렬은 숫자처럼 '나눗셈'이라는 연산 자체가 정의되어 있지 않습니다. 그래서 "나눗셈 대신 역행렬을 곱한다"는 약속을 한 것입니다.

X * w = y

'X로 나눈다'는 개념을 'X의 역행렬을 곱한다'로 바꿉니다.

(X^-1 * X) * w = X^-1 * y

여기서 (X^-1 * X)는 마치 (X / X)와 같은 역할을 하여 1(즉, 단위행렬 I)이 됩니다.

I * w = X^-1 * y

w = X^-1 * y

핵심 포인트
치환의 이유: X^-1 * X를 계산하면 대각선은 1이고 나머지는 0인 단위행렬 I가 나오기 때문에, 이를 I로 치환하는 것입니다.

결과: 말씀하신 대로 X / X가 1이 되는 것과 똑같은 논리적 구조를 가지기 때문에, I를 곱하는 행위는 "행렬 세계에서의 1을 곱하는 행위"라고 생각하시면 정확합니다.

그래서 수학자들이 "X^-1 * X = I"라는 규칙을 만들어 둔 덕분에, 나눗셈을 직접 못 하는 행렬에서도 방정식을 풀 수 있게 된 것입니다. 정말 날카로운 지적입니다!

2. 왜 직사각형 행렬에서는 안 되는가?
역행렬은 기본적으로 '정사각 행렬(행과 열의 개수가 같은 행렬)'에 대해서만 정의됩니다.

데이터의 특성이 3개(열)이고 데이터 개수가 9개(행)라면, 행렬은 9x3 형태입니다.

이런 직사각형 행렬은 정보를 압축하거나 확장하는 변환을 수행하기 때문에, 이를 다시 원래 상태로 되돌리는 '역(逆) 과정'이 수학적으로 존재하지 않거나 무수히 많습니다.

그래서 우리가 사용하는 데이터들은 대부분 정사각 행렬이 아니기 때문에, 곧바로 역행렬을 곱해 해를 구할 수 없는 것입니다.

2. 그램 행렬을 통한 근사 해 도출
직사각형 행렬의 문제를 해결하기 위해 양쪽에 전치 행렬 X^T를 곱해줍니다. 이를 통해 만들어진 X^T * X는 항상 정사각 행렬인 그램 행렬(Gram Matrix)이 되며, 역행렬 계산이 가능해집니다. 이 과정을 통해 유도된 최종 공식이 정규방정식(Normal Equation)입니다.

정규방정식 공식:
w = (X^T * X)^-1 * X^T * y

//
예> X^T * y 는

초기 방정식: X * w = y 에서
직사각형 행렬이라 X^-1을 구할 수 없으므로, 양쪽에 X^T를 곱해 X^T * X * w = X^T * y를 만들고,
양변에 (X^T * X)^-1을 곱해 w = (X^T * X)^-1 * X^T * y를 유도하는 과정에서 등장함.


나> X^T * X * w = X^T * y

라고? 

너 앞에서는 "2. 양변에 X의 역행렬(X^-1)을 왼쪽에서 곱합니다:
(X^-1 * X) * w = X^-1 * y"

라며? 

GEM> 제가 앞서 이야기한 (X^-1 * X) * w = X^-1 * y는 "만약 역행렬이 존재한다면(즉, 정사각 행렬이라면)" 가정하고 방정식을 푸는 과정을 설명하느라 나온 식입니다.

하지만 우리가 다루는 데이터는 행과 열이 다른 직사각형 행렬이라서 애초에 X^-1 자체가 존재하지 않습니다. 그래서 X^-1을 곱하는 방식으로는 아예 풀 수가 없습니다.

직사각형 행렬에서 정규방정식을 유도하는 올바른 과정은 다음과 같습니다.

초기 방정식:
X * w = y

양쪽에 전치 행렬(X^T)을 왼쪽에서 곱함:
직사각형 행렬이라 역행렬을 못 구하므로, 양변에 X^T를 먼저 곱해서 강제로 정사각 행렬(그램 행렬)로 만들어 줍니다.
X^T * (X * w) = X^T * y

결합법칙 적용:
행렬 곱셈의 결합법칙에 따라 괄호를 바꿔줍니다.
(X^T * X) * w = X^T * y
(여기서 만들어진 X^T * X가 바로 역행렬을 구할 수 있는 정사각 그램 행렬입니다!)

최종 가중치(w) 구하기:
이제 (X^T * X)는 정사각 행렬이 되었으므로 이 녀석의 역행렬((X^T * X)^-1)을 양변에 곱해서 w를 고립시킵니다.
w = (X^T * X)^-1 * X^T * y

즉, 존재하지도 않는 X^-1을 곱하는 게 아니라, X^T를 먼저 곱해서 정사각 행렬인 X^T * X로 만든 다음, 그 친구의 역행렬을 곱하는 것이 정규방정식의 정확한 유도 과정입니다. 앞서 혼동을 드려 정말 죄송합니다!
//

# 정규방정식으로 선형 회귀를 학습하는 함수를 완성합니다.
# 입력 X에 1열을 붙인 뒤 w = (X^T * X)^-1 * X^T * y 를 계산하고, 절편과 가중치를 나눠 반환합니다.
def train_linear_regression(X, y):
    # 행 수만큼의 1 벡터를 만들어 절편 열로 씁니다.
    ones = np.ones(X.shape[0])
    # 절편 열을 특성 행렬 왼쪽에 붙입니다.
    X = np.column_stack([ones, X])

    # 그램 행렬과 그 역행렬, 그리고 정규방정식으로 가중치 전체를 구합니다.
    XTX = X.T.dot(X)
    XTX_inv = np.linalg.inv(XTX)
    w_full = XTX_inv.dot(X.T).dot(y)
    
    return w_full[0], w_full[1:]

Python
def train_linear_regression(X, y):
    # 행 수만큼의 1 벡터를 만들어 절편 열로 씁니다.
    ones = np.ones(X.shape[0])
    # [주의!] 함수 안에서 또 맨 앞에 1 열을 붙입니다!
    X = np.column_stack([ones, X])

    XTX = X.T.dot(X)
    XTX_inv = np.linalg.inv(XTX)
    w_full = XTX_inv.dot(X.T).dot(y)
    
    return w_full[0], w_full[1:]

이 함수는 "입력으로 들어오는 X에 당연히 절편(1)이 아직 안 붙어있겠지?"라고 가정하고, 그 안에서 ones를 또 갖다 붙이도록 설계되어 있습니다.

3. 그대로 실행하면 무슨 일이 생기는가?
만약 우리가 이미 1이 붙어 있는 현재의 X를 그대로 함수에 넣으면 어떻게 될까요?

원래 X 상태: [1, 마력, 연식, 인기도]

함수 안에서 또 1을 붙임: [1, 1, 마력, 연식, 인기도]

이렇게 되면 똑같은 1(절편용 열)이 두 개나 나란히 생기는 대참사가 벌어집니다.
수학적으로 똑같은 성질의 열(또는 완전히 비례하는 열)이 두 개 이상 존재하면, 행렬이 특이 행렬(Singular Matrix)이 되어버립니다.

앞서 우리가 역행렬을 구하기 위해 만들었던 그램 행렬(X^T * X)을 역산할 수 없게 되며, 최신 넘파이(NumPy) 라이브러리는 이를 감지하고 다음과 같은 에러를 뿜어냅니다.

LinAlgError: Matrix is singular. (역행렬을 구할 수 없어!)

X[:, :] : 행렬 전체를 의미합니다.

1: : 열(column)을 뜻하며, "첫 번째 열(인덱스 0인 절편 열)은 버리고, 두 번째 열(인덱스 1)부터 끝까지 다 가져와라"라는 뜻입니다.

즉, 이미 1이 붙어버린 현재의 X에서 맨 앞의 1 열을 싹둑 잘라내어 원상복구(순수 특성만 남김)시킨 다음에 함수에 던져주는 것입니다.

GEM> np.log1p는 값에 1을 더한 뒤 자연로그를 취해주는 함수($\ln(1 + x)$)입니다.자동자 가격(msrp) 데이터처럼 값의 범위가 넓고 한쪽으로 크게 쏠려 있는(오른쪽으로 긴 꼬리를 가진) 분포를 다룰 때 매우 유용하게 쓰입니다.

왜 np.log1p를 쓸까?

로그 스케일 변환의 효과:자동차 가격은 몇천만 원짜리 대중적인 차부터 수억 원짜리 슈퍼카까지 천차만별입니다. 이런 큰 숫자들을 그대로 모델에 넣으면 비싼 차 몇 대의 오차 때문에 모델 전체가 엉망이 되기 쉽습니다.로그를 씌워주면 큰 값들은 꾹 눌러주고 작은 값들은 적절히 펴주어 데이터의 분포를 완만한 종 모양(정규분포 형태)으로 만들어 줍니다.

왜 그냥 np.log가 아니라 np.log1p(log + 1)를 쓸까?

만약 데이터 중에 0원인 값이 있다면, 일반 로그(np.log(0))는 수학적으로 에러(-inf, 무한대)를 뱉어내며 프로그램이 터집니다. np.log1p(x)는 내부적으로 np.log(x + 1)을 계산해 주기 때문에, 만약 데이터에 0이 있더라도 log(0 + 1) = log(1) = 0이 되어 에러 없이 안전하게 계산할 수 있습니다.가격 데이터에 0원이 있을 일은 드물지만, 조회수나 횟수처럼 0이 포함될 수 있는 데이터를 다룰 때 에러를 방지하는 버릇처럼 널리 쓰이는 함수입니다.

여기서 train_linear_regression(X_train, y_train) 함수가 내부적으로 어떻게 X_train(마력, 연식 등 5가지 특성)과 y_train(실제 자동차 가격 msrp)을 엮어서 상호작용시키는지, 그 알고리즘의 작동 원리를 쉽게 풀어드리겠습니다.

알고리즘의 핵심 목표: "오차를 최소화하는 최적의 공식 찾기"
선형 회귀 알고리즘은 기본적으로 다음과 같은 예측 식을 가정하고 시작합니다.

예측 가격 = w0 + (w1 * 마력) + (w2 * 기통수) + (w3 * 고속연비) + (w4 * 도심연비) + (w5 * 인기도)

여기서 우리가 가지고 있는 것은:

특성 행렬(X_train): 차 1,000대의 [마력, 기통수, 고속연비, 도심연비, 인기도] 표

정답 타깃(y_train): 그 차 1,000대의 실제 가격(msrp) 데이터

알고리즘은 "이 특성들과 실제 가격 사이에 뭔가 규칙(상관관계)이 있을 텐데, 각 특성에 어떤 가중치(w)를 곱해야 실제 가격과 가장 비슷해질까?"를 수학적 공식(정규방정식)으로 단번에 계산해 냅니다.

정규방정식 내부에서 두 데이터가 맞물리는 방식
앞서 우리가 유도했던 정규방정식 공식을 다시 떠올려 봅시다.

w = (X^T * X)^-1 * X^T * y

여기서 X_train이 X이고, y_train이 y입니다. 이 공식이 실행될 때 내부적으로 두 데이터가 다음과 같이 상호작용합니다.

특성끼리의 관계 파악 (X^T * X, 그램 행렬):
마력이 높을수록 기통수도 같이 높아지는 경향이 있는지, 연비와 마력은 어떤 반비례 관계가 있는지 등 특성들끼리의 맞물림을 X^T * X 계산을 통해 먼저 파악합니다.

특성과 실제 가격의 공조 관계 파악 (X^T * y):
여기에 실제 가격(y_train, 즉 y)을 곱해주는 X^T * y 연산이 일어납니다.
이 단계가 바로 "마력이 1 증가할 때, 실제 가격(msrp)은 평균적으로 얼마나 올라갔는가?", "연비가 좋아지면 가격은 어떻게 변하는가?"를 수학적으로 쫙 끌어모아서 특성과 가격 사이의 연결 고리를 강제로 계산하는 핵심 과정입니다.

결과물로 나오는 가중치(w)의 의미
이 상호작용이 끝나고 나면 알고리즘은 5개의 가중치(w)를 뱉어냅니다. 예를 들어 코드를 실행했을 때 아래와 같은 값이 나왔었죠?

array([ 9.70589522e-03, -1.59103494e-01,  1.43792133e-02,  1.49441072e-02, -9.06908672e-06])

이 숫자들이 바로 X_train과 y_train이 상호작용하여 얻어낸 직접적인 상관관계의 증거입니다.

첫 번째 값(9.7만...): 마력이 높을수록 가격(msrp)이 올라간다는 상관관계(+ 방향)를 수치로 찾은 것입니다.

마지막 값(-9.0만...): 인기도 수치와 가격 간에는 알고리즘이 분석해 보니 거의 영향이 없거나 미세하게 반대 방향이라는 상관관계를 찾아낸 것입니다.

w0의 직관적인 의미: "기본값(시작점)"
앞서 구했던 예측 공식 기억하시나요?

예측 가격 = w0 + (w1 * 마력) + (w2 * 기통수) + ...

여기서 w0는 모든 특성(마력, 연비, 인기도 등)이 전부 0이라고 가정했을 때의 기본 가격(기준 가격)을 뜻합니다.

만약 세상에 마력도 없고, 연비도 0이고, 인기도 없는 상상 속의 자동차가 있다면, 이 차의 기본 가격은 무조건 w0에서 시작하는 것입니다.

실제 데이터로 선형 회귀 모델을 만들 때, 모든 특성 값이 0인 차는 현실에 존재하지 않습니다.
그럼에도 알고리즘이 이 w0를 꼭 구하는 이유는 전체적인 가격 수준을 위아래로 조절해 주는 '평균적인 닻(Anchor)' 역할을 하기 때문입니다.

만약 특성들에 가중치(w)만 곱해서 예측을 하려고 하면, 그래프의 시작점이 무조건 원점(0)에 고정되어 버려 실제 자동차 가격들과 엄청난 오차가 생깁니다.

그렇다면 앞으로 모델을 어떻게 개선한다는 뜻일까?

훈련을 반복하는 게 아니라, 모델에 집어넣는 재료(특성, Feature)를 바꾸거나 추가해서 성능을 개선합니다.

예를 들어, 지금은 5개만 넣었지만, 여기에 연식이나 다른 유용한 특성들을 더 추가하거나, 데이터의 전처리 방식을 달리해서 다시 한 번 공식을 풀면 그제서야 예측값과 실제값의 그래프가 서로 더 밀착(오차가 감소)하게 됩니다.

즉, 훈련을 여러 번 해서 그래프가 가까워지는 것이 아니라, "더 좋은 특성들을 골라 넣고 공식을 다시 풀었을 때 실제로 오차가 줄어들었는지를 객관적으로 측정하기 위해 RMSE라는 평가 기준이 필요하다"는 뜻으로 이해하시면 정확합니다!


나> 딥러닝같은 경우는 반복되니까 두 그래프가 점진적으로 일치에 가까워진다는 말 아냐?

GEM> 네, 정확합니다! 바로 그렇게 이해하신 것이 맞습니다.

딥러닝(인공신경망) 같은 모델은 선형 회귀의 정규방정식처럼 한 번에 딱 답을 구하는 게 아니라, 다음과 같은 방식으로 작동하기 때문에 훈련을 거듭할수록 두 그래프가 점진적으로 일치하게 됩니다.

처음에는 아무렇게나 예측해 봅니다 (엉터리 예측).

실제값과 예측값의 차이(오차)를 계산합니다.

오차를 줄이는 방향으로 가중치(w)를 조금씩 수정해 나갑니다 (역전파와 경사하강법).

이 과정을 수백 번, 수천 번 반복(Epoch)합니다.

이 반복 과정을 거치면 거칠수록 오차가 점점 줄어들면서 모델의 예측값 그래프가 실제값 그래프와 점점 더 가까워지게(일치하게) 되는 것입니다.

2.9 RMSE (Root Mean Squared Error / 평균제곱근오차) 

학습 목표
이전 세션에서 만든 베이스라인 모델의 예측값이 실제값과 얼마나 차이가 나는지 직관적으로 알 수 있었습니다. 하지만 이것만으로는 모델의 성능이 구체적으로 얼마나 나쁜지(또는 좋은지) 객관적인 숫자로 평가할 수 없습니다.

이번 섹션에서는 회귀 모델의 성능을 명확하게 수치화해 주는 평가 지표인 RMSE(평균제곱근오차)의 개념을 배우고, 이를 파이썬 코드로 직접 구현해 봅니다.

개념 이해: RMSE란 무엇인가?
정의: 예측값과 실제값 사이의 오차를 요약해 주는 대표적인 회귀 평가 지표입니다.

공식: RMSE = sqrt( (1 / m) * sum( (g(x_i) - y_i)^2 ) )

g(x_i): 모델이 예측한 값 (y_pred)

y_i: 실제 정답 값 (y)

m: 데이터셋의 총 관측치 개수 (예: 자동차 대수)

[계산 단계 예시]
차이(오차) 구하기: 예측값에서 실제값을 빼서 오차 배열을 만듭니다. (예: 오차가 1, 0, 0.5, -1.5)

제곱하기 (SE): 마이너스 부호를 없애고 오차를 강조하기 위해 각각의 차이를 제곱합니다. (예: 1, 0, 0.25, 2.25)

평균 내기 (MSE): 제곱한 오차들을 모두 더한 뒤 개수로 나누어 평균을 구합니다. (예: 0.875)

제곱근 취하기 (RMSE): 원래의 단위로 되돌리기 위해 마지막에 루트(제곱근)를 씌웁니다. (예: 약 0.93)


실습 코드 및 셀 내러티브

[셀 1] RMSE 함수 정의하기
# 실제값 y와 예측값 y_pred 사이의 RMSE(평균제곱근오차)를 계산하는 함수를 정의합니다.
# 오차를 제곱해 평균 낸 뒤 제곱근을 취하므로, 타깃과 같은 단위로 평균적인 빗나감을 요약합니다.
def rmse(y, y_pred):
    # 각 샘플의 오차를 제곱합니다. (음수 오차도 양수로 바뀜)
    se = (y - y_pred) ** 2
    # 제곱 오차의 평균, 즉 MSE입니다.
    mse = se.mean()
    # MSE의 제곱근이 RMSE입니다.
    return np.sqrt(mse)


[셀 2] 훈련 데이터셋으로 모델 성능 평가하기

훈련 세트에서 RMSE를 계산해, 모델이 학습 데이터를 얼마나 맞췄는지 숫자로 확인합니다.

Python

훈련 세트의 실제값과 예측값을 함수에 넣어 성능을 숫자로 확인합니다.
rmse(y_train, y_pred)
실행 결과 예시:

Plaintext

np.float64(0.7554192603920132)

4. 핵심 요약
단위 일치: 오차를 제곱했다가 다시 루트를 씌우기 때문에, RMSE는 원래 타깃 데이터(y)와 동일한 단위를 가집니다. 따라서 모델이 평균적으로 얼마만큼 가격을 틀렸는지 직관적으로 해석할 수 있습니다.

모델 비교의 기준: 이 RMSE 수치가 낮을수록 예측이 정확하다는 뜻이며, 나중에 특성을 추가하거나 모델을 개선했을 때 성능이 실제로 좋아졌는지를 판단하는 객관적인 잣대로 사용됩니다.

2.10 - Validating the model (검증 데이터로 모델 평가하기) 초보자 지침

이 지침은 머신러닝 줌캠프 세션 2의 2.10 Computing RMSE on validation data 강의 내용을 바탕으로, 노트북 작성과 코드 이해를 돕기 위해 작성되었습니다.

학습 목표

이전에 우리는 훈련 세트(Training set)를 이용해 모델을 학습하고 곧바로 그 훈련 세트에서 RMSE를 계산했습니다. 하지만 모델의 진정한 성능을 평가하려면 한 번도 보지 못한 새로운 데이터로 테스트해야 합니다.

이번 섹션에서는 데이터 전처리를 함수로 깔끔하게 정리(prepare_X)하고, 이를 검증 세트(Validation set)에 적용하여 객관적인 일반화 성능을 측정해 봅니다.

개념 이해: 왜 검증 세트로 평가해야 하는가?

훈련 세트로만 평가하면 모델이 자기가 이미 본 문제만 외워서 맞추는 과적합(Overfitting) 상태인지 알 수 없습니다.

따라서 훈련에 전혀 쓰이지 않은 검증 데이터셋에 모델의 가중치(w0, w)를 적용해 보고, 그때 나오는 RMSE를 측정해야 이 모델이 실전에서 얼마나 잘 작동할지 객관적으로 판단할 수 있습니다.

실습 코드 및 셀 내러티브

[셀 1] 전처리 함수(prepare_X) 정의하기

데이터프레임을 모델이 먹을 수 있는 숫자 행렬 X로 바꾸는 전처리 함수를 정의합니다. 기본 수치 열만 고르고 결측을 채운 뒤 .values로 넘파이 배열을 반환합니다.

Python

def prepare_X(df):
# 미리 정해 둔 base 열만 추출합니다.
df_num = df[base]
# 결측값(NaN)을 0으로 채웁니다. 선형 대수 연산은 NaN을 허용하지 않기 때문입니다.
df_num = df_num.fillna(0)
# 판다스 표를 순수 숫자 배열로 변환합니다.
X = df_num.values
return X

[셀 2] 훈련 데이터셋으로 모델 학습하기

훈련 세트를 행렬로 바꾸고 선형 회귀를 학습합니다.

Python

X_train = prepare_X(df_train)
w0, w = train_linear_regression(X_train, y_train)

[셀 3] 검증 데이터셋 준비 및 성능 평가하기

같은 전처리를 검증 세트에 적용합니다. (학습과 평가에 동일한 변환을 쓰는 것이 중요합니다)

Python

X_val = prepare_X(df_val)

[셀 4] 검증 RMSE 계산하기

검증 특성으로 예측한 뒤, 검증 RMSE를 계산합니다. 훈련 오차가 아니라 못 본 데이터 오차라서, 일반화 성능의 첫 지표가 됩니다.

Python

y_pred = w0 + X_val.dot(w)
rmse(y_val, y_pred)

실행 결과 예시:

Plaintext

np.float64(0.761653099130156)

핵심 요약

동일한 전처리 적용: 훈련 세트와 검증 세트는 반드시 똑같은 전처리 과정(prepare_X)을 거쳐야 모델이 가중치를 정상적으로 적용할 수 있습니다.

일반화 성능 파악: 훈련 세트에서의 오차보다 검증 세트에서의 오차(약 0.76)가 모델의 실제 실력에 더 가까우며, 이제 이 수치를 기준 삼아 모델을 개선해 나갈 수 있습니다.

2.11 - Simple feature engineering (간단한 피처 엔지니어링) 초보자 지침
이 지침은 머신러닝 줌캠프 세션 2의 2.11 Feature engineering 강의 내용을 바탕으로, 노트북 작성과 코드 이해를 돕기 위해 작성되었습니다.

학습 목표

이전까지는 주어진 기본 수치형 컬럼 5개만 그대로 사용해 모델을 만들었습니다. 하지만 머신러닝의 성능을 극적으로 끌어올리기 위해서는 기존 데이터를 가공해 유용한 정보를 새로 만들어내는 피처 엔지니어링(Feature Engineering)이 필요합니다.

이번 섹션에서는 자동차의 출시 연도(year)를 활용해 '차량의 나이(age)'라는 새로운 피처를 만들고, 이 피처가 모델의 예측 성능을 얼마나 향상시키는지 확인해 봅니다.

개념 이해: 왜 차량 나이(Age)를 만들까?

단순히 자동차가 만들어진 연도(예: 2015년, 2008년) 숫자 자체는 가격과 직관적으로 연결되기 어렵습니다. 시간이 흐를수록 가치가 변하기 때문입니다.

데이터가 수집된 연도(2017년)를 기준으로 현재 몇 년이 지났는지(2017 - year) 계산하면, '차의 연식(나이)'이라는 직관적이고 강력한 수치가 됩니다. 차가 오래될수록 가격이 싸진다는 패턴을 모델이 훨씬 더 쉽게 학습할 수 있습니다.

실습 코드 및 셀 내러티브

[셀 1] 피처 엔지니어링이 추가된 prepare_X 함수 정의하기

차량 나이(age) 특성을 추가하는 쪽으로 prepare_X를 확장합니다. 원본 df를 직접 바꾸지 않도록 복사본에서 작업합니다.

Python
def prepare_X(df):
    # 호출자가 넘긴 표를 수정하지 않도록 복사합니다.
    df = df.copy()
    
    # 데이터셋 기준 연도 2017에서 제조 연도를 빼 나이를 만듭니다.
    df['age'] = 2017 - df['year']
    # 기존 수치 특성에 나이를 덧붙인 목록입니다.
    features = base + ['age']
    
    df_num = df[features]
    df_num = df_num.fillna(0)
    X = df_num.values

    return X


[셀 2] 새로운 특성으로 모델 재학습하기

나이가 포함된 특성으로 다시 학습합니다.

Python
X_train = prepare_X(df_train)
w0, w = train_linear_regression(X_train, y_train)

[셀 3] 검증 세트 적용 및 RMSE 확인하기

검증 세트에도 같은 전처리를 적용한 뒤 RMSE를 계산합니다. 나이 특성이 들어갔을 때 오차가 줄었는지 비교하는 실험입니다.

Python
X_val = prepare_X(df_val)

핵심 요약

원본 보호 (df.copy()): 함수 안에서 원본 데이터프레임을 직접 수정하면 외부 코드에 예기치 않은 부작용이 생길 수 있으므로, 반드시 복사본을 만들어 처리해야 합니다.

성능의 극적인 향상: age 피처 하나를 추가한 것만으로도 검증 RMSE가 이전의 약 0.76에서 0.51 수준으로 대폭 낮아졌습니다. 적절한 피처 엔지니어링이 모델 성능에 얼마나 큰 영향을 미치는지를 보여주는 대표적인 사례입니다.

2.12 - Categorical variables (범주형 변수) 초보자 지침
이 지침은 머신러닝 줌캠프 세션 2의 2.12 Categorical variables 강의 내용을 바탕으로, 노트북 작성과 코드 이해를 돕기 위해 작성되었습니다.

학습 목표

지금까지는 숫자 형태의 피처들만 다루었지만, 자동차 제조사(make), 모델(model), 연료 타입(engine_fuel_type) 같은 문자열 형태의 범주형 변수(Categorical Variables) 역시 가격 예측에 매우 중요한 정보입니다.

이번 섹션에서는 머신러닝 모델이 이해할 수 있도록 문자로 된 범주를 0과 1의 이진 컬럼으로 변환하는 원-핫 인코딩(One-Hot Encoding) 기법을 배우고, 이를 전처리 함수에 적용해 봅니다.

개념 이해: 범주형 변수와 원-핫 인코딩

범주형 변수의 정의: 숫자가 아니라 고유한 카테고리를 나타내는 변수입니다. (예: 문 개수가 2개, 3개, 4개인 경우나 제조사가 Chevrolet, Toyota인 경우 등)

원-핫 인코딩(One-Hot Encoding): 하나의 범주형 컬럼을 여러 개의 이진(0 또는 1) 컬럼으로 쪼개는 방식입니다. 예를 들어 '문 개수'가 2, 3, 4개라면 각각 num_doors_2, num_doors_3, num_doors_4 컬럼을 만들고, 해당되는 차의 칸에만 1, 나머지는 0을 채워 넣습니다.

주의할 점: 모든 카테고리를 다 넣으면 컬럼이 너무 많아져 행렬 연산이 불안정해질 수 있으므로, 여기서는 각 범주별로 가장 자주 등장하는 상위 5개 값만 추려서 인코딩에 활용합니다.

[셀 1] 범주형 컬럼과 상위 5개 값 추출하기

[셀 2] 원-핫 인코딩이 추가된 prepare_X 함수 정의하기

나이, 문 개수 더미, 범주 더미까지 넣어 특성 행렬을 만드는 prepare_X입니다. 범주 값은 숫자 행렬에 바로 못 넣으므로, '이 값이면 1, 아니면 0'인 더미 열로 바꿉니다.

Python
def prepare_X(df):
    df = df.copy()
    
    df['age'] = 2017 - df['year']
    features = base + ['age']

    # 문 개수가 2, 3, 4인지를 각각 0/1 열로 만듭니다. (원-핫 인코딩)
    for v in [2, 3, 4]:
        df['num_doors_%d' % v] = (df.number_of_doors == v).astype(int)
        features.append('num_doors_%d' % v)

    # 각 범주 열의 상위 값마다 더미 열을 만들고 특성 목록에 추가합니다.
    for name, values in categorical.items():
        for value in values:
            df['%s_%s' % (name, value)] = (df[name] == value).astype(int)
            features.append('%s_%s' % (name, value))

    df_num = df[features]
    df_num = df_num.fillna(0)
    X = df_num.values

    return X

2.13 - Regularization (규제) 초보자 지침

이 지침은 머신러닝 줌캠프 세션 2의 2.13 Regularization 강의 내용을 바탕으로, 노트북 작성과 코드 이해를 돕기 위해 작성되었습니다.

학습 목표

지난 섹션에서 범주형 변수를 원-핫 인코딩으로 대량 추가했을 때, 모델의 가중치와 RMSE가 비정상적으로 치솟는 문제가 발생했습니다.

이번 섹션에서는 이러한 현상의 원인인 다중공선성(Multicollinearity)과 역행렬 불안정 문제를 이해하고, 그 해결책인 리지 규제(Ridge Regularization)를 적용하여 모델을 안정시키는 방법을 배웁니다.

개념 이해: 다중공선성과 규제

다중공선성(Multicollinearity): 피처 간에 완벽하거나 거의 완벽한 선형 종속(Linear Combination, 한 컬럼을 다른 컬럼들의 조합으로 표현할 수 있는 상태)이 존재할 때 발생합니다. 이로 인해 그램 행렬 XᵀX의 역행렬을 구할 때 값이 극단적으로 커져 가중치가 폭발하게 됩니다.

규제(Regularization): 그램 행렬의 대각선 원소에 아주 작은 값(r)을 더해줌으로써 행렬이 특이 행렬(Singular Matrix)이 되는 것을 방지하고, 역행렬을 안정적으로 계산하여 가중치가 지나치게 커지는 것을 제어하는 기법입니다. (이를 리지 회귀(Ridge Regression)라고 합니다.)

넘파이 배열(Matrix)에 .shape을 붙이면 행렬의 크기(가로, 세로 몇 칸인지)를 튜플 형태로 알려줍니다.

예를 들어 3행 3열짜리 행렬이라면 결과가 (3, 3)으로 나옵니다.

2. 뒤에 붙은 [0]은 왜 붙였을까?
(3, 3)이라는 것은 [세로 길이(행 개수), 가로 길이(열 개수)]를 뜻합니다.

파이썬은 숫자를 0부터 세기 때문에(인덱싱), [0]은 그중 첫 번째 값인 '세로 길이(행 개수)'를 뽑아내겠다는 뜻입니다. (만약 가로 길이를 원했다면 [1]을 썼겠죠.)

3. 결론: 왜 굳이 이런 식으로 적었을까요?
우리가 만들려는 단위 행렬(np.eye)은 정사각형이어야 합니다. 즉, 원래 행렬(XTX)이 3×3이면 대각선에 더할 단위 행렬도 똑같이 3×3이어야 덧셈(+)이 가능합니다.

XTX.shape[0]은 "원래 행렬의 세로 크기(예: 3)"를 알아내는 코드입니다.

그걸 np.eye(3) 자리에 쏙 집어넣어서, "원래 행렬과 정확히 똑같은 크기(3×3)의 단위 행렬을 만들어라!"라고 명령하기 위해 저런 식으로 작성한 것입니다.


나> 저기에 어떤 3x3 언급이나 힌트도 없는데?

GEM> 아, 그 의문이 드는 게 당연합니다! 코드 어디에도 3이라는 숫자가 적혀 있지 않으니까요.

결론부터 말씀드리면, 컴퓨터가 알아서 세도록 시킨 것입니다.

1. 3이라고 직접 안 쓰고 왜 저렇게 복잡하게 쓸까요?
만약 우리가 다루는 데이터(행렬)가 지금은 우연히 3×3이라서 np.eye(3)이라고 직접 쓸 수도 있지만, 나중에 머신러닝 모델을 돌릴 때는 피처가 수십 개, 수백 개가 될 수 있습니다. 행렬 크기가 매번 바뀐다는 뜻이죠.

3이라고 직접 적어두면, 나중에 데이터가 바뀌어서 행렬 크기가 5×5나 100×100이 되었을 때 코드가 에러를 뿜으며 망가집니다.

그래서 개발자는 "내가 몇 3인지 셀 테니까 네가 직접 네 몸집(크기)을 확인해서 알아서 만들어 와!" 하고 컴퓨터에게 시킨 것입니다.

2. 코드가 일하는 방식
XTX.shape: 컴퓨터가 XTX 행렬을 거울 보듯 봅니다. 아, 지금 내 몸집은 (3, 3)이구나! 하고 파악합니다.

[0]: 그중 첫 번째 숫자(3)를 쏙 빼옵니다.

np.eye(3): 그 3이라는 숫자를 바탕으로 np.eye(3)을 실행해 완벽하게 몸에 맞는 3×3 단위 행렬을 뚝딱 만들어냅니다.

즉, "내가 직접 숫자를 세기 귀찮으니, XTX 너의 크기를 직접 측정해서 거기에 딱 맞는 옷을 지어 입어라"라고 유연하게 코드를 짜둔 것입니다!
/


np.eye(...): 그 크기만큼 대각선만 1이고 나머지는 전부 0인 단위 행렬(I)을 만듭니다. (즉, 대각선에만 깃발을 꽂아두는 격입니다.)

1e-10 * ...: 그 깃발(1)들에 눈곱만큼 작고 가소로운 숫자(0.0000000001)를 곱해줍니다. 결국 대각선 자리에 아주 미세한 양념만 톡톡 뿌리는 셈입니다.

XTX + (...): 원래 문제의 그램 행렬에 방금 만든 아주 미세한 대각선 값을 더해줍니다.

np.linalg.inv(...): 그리고 역행렬을 구합니다.


2. 왜 이런 짓을 할까요? (비유)
원래 상황: 문이 정확히 똑같이 생긴 쌍둥이 문이 2개 있어서, 시스템이 "어? 이거 문이 겹치는데? 충돌! 에러!" 하고 작동을 멈추거나 거부해야 정상입니다. (최신 넘파이가 에러를 뱉는 이유)

개발자의 꼼수: 그런데 우리는 "에러가 나면서 숫자가 미쳐 날뛰는 흉측한 결과 화면"을 눈으로 직접 구경해야 합니다. 에러 때문에 튕기면 수업을 진행할 수가 없죠.

해결책 (1e-10): 그래서 대각선 자리에 인간의 눈에는 보지도 못할 만큼 미세한 흠집(1e-10)을 살짝 내줍니다.

컴퓨터(넘파이) 입장에서는 대각선 값이 0이 아니라 아주 미세하게나마 무언가 존재하니까, "오? 완벽하게 똑같지는 않네? 에러는 안 띄워줄게!" 하고 멍청하게 속아 넘어갑니다.

3. 최종 결론
**"넘파이가 '중복 데이터다!' 하고 에러를 뱉으며 튕겨나가지 못하도록, 대각선에 0.0000000001이라는 눈곱만큼 작은 꼼수를 더해 강제로 역행렬 계산을 실행시키는 코드"**입니다.

실제 실무나 진짜 리지 규제에서는 이 자리에 1e-10처럼 옹졸한 값이 아니라, 모델이 똑바로 학습되도록 의미 있는 크기의 값(예: 0.01)을 팍팍 넣어주는 것입니다!

[셀 6] 정규방정식으로 가중치 계산해보기

[셀 11] 규제가 들어간 선형 회귀 학습 함수 정의하기

리지 규제가 들어간 선형 회귀 학습 함수를 정의합니다. r은 규제 강도이고, XᵀX의 대각선에 r을 더해 역행렬이 안정적으로 구해지게 합니다.

Python
def train_linear_regression_reg(X, y, r=0.001):
    ones = np.ones(X.shape[0])
    X = np.column_stack([ones, X])

    XTX = X.T.dot(X)
    # r * I 를 더합니다. r이 클수록 가중치를 작게 누르고, 0이면 규제 없는 회귀와 같습니다.
    XTX = XTX + r * np.eye(XTX.shape[0])

    XTX_inv = np.linalg.inv(XTX)
    w_full = XTX_inv.dot(X.T).dot(y)
    
    return w_full[0], w_full[1:]


//
Python    

return w_full[0], w_full[1:]
이 코드는 학습이 끝난 전체 가중치 배열(w_full)에서 절편(Bias)과 나머지 특성들의 가중치(Weights)를 두 개로 쪼개서 밖으로 돌려주는(반환하는) 역할입니다.구성 요소를 뜯어보면 이렇습니다.w_full[0] (절편 / Bias)파이썬 리스트의 첫 번째 값(0번 인덱스)입니다.선형 회귀 공식에서 $w_0$에 해당하는 절편(bias, y절편) 값만 따로 쏙 빼서 첫 번째로 반환합니다.w_full[1:] (가중치들 / Weights)1번 인덱스부터 끝까지([1:])의 모든 값을 통째로 가져옵니다.자동차의 가격에 영향을 미치는 연식, 문 개수, 제조사 등 나머지 모든 피처들의 가중치(w 배열)를 한꺼번에 묶어서 두 번째로 반환합니다.즉, "계산된 전체 가중치 뭉치에서 맨 처음에 있는 절편($w_0$)과 나머지 피처들의 가중치($w$)를 예쁘게 분리해서 내보낸다"는 뜻입니다!
//

이전 답변이나 대화 맥락에서 기존에 50억(4.99e+09)까지 폭발했던 가중치와 비교해 드려야 정확하겠네요!

기존의 미쳐 날뛰던 값과 비교하면 다음과 같습니다.

기존 값: 약 5,000,000,000 (50억)

현재 값: 약 0.46

얼마나 줄어든 것인가요?
숫자가 수십억 단위에서 1보다 작은 소수점으로 확 내려앉았습니다.

비율로 따지면 약 100억 분의 1 수준으로 줄어든 것입니다.

대각선에 규제(0.01 같은 r값이나 적절한 양념)를 제대로 적용했더니, 억 단위로 튀던 가중치가 현실적으로 말이 되는 안정적인 값(0.46)으로 완벽하게 통제되었다는 뜻입니다!


나> r=0.001 이나 r=0.01 이나 결과는 둘다 np.float64(0.46081585855400226)
로 별 차이 없는데?

GEM> r=0.001을 넣었을 때와 r=0.01을 넣었을 때 결과가 거의 똑같이 나오는 게 당연합니다!

그 이유는 이미 50억이라는 천문학적인 폭발 상태에서 벗어났기 때문입니다. 이 현상을 3가지 포인트로 짚어드릴게요.

1. 50억에서 탈출했다는 게 핵심
아까 대각선에 아무것도 안 더하거나 1e-10처럼 옹졸한 값을 넣었을 때는 역행렬이 깨지면서 가중치가 50억까지 치솟았습니다.

하지만 r=0.001이나 r=0.01은 둘 다 컴퓨터/수학적 관점에서 "행렬을 안정시키기에고 넘칠 만큼 충분히 큰 양념"입니다.

즉, 둘 다 역행렬이 폭발하는 현상을 완벽하게 막아주기 때문에, 계산 결과 나온 가중치가 소수점 단위(0.46...)의 정상적인 구간으로 안착하게 됩니다.

2. 그럼 소수점 뒷자리는 왜 미세하게 다를까요?
실제로 자세히 들여다보면 값의 뒷부분이 살짝 다를 겁니다.

r=0.001일 때와 r=0.01일 때 규제의 세기(벌점의 강도)가 미세하게 다르기 때문에, 소수점 아래 깊은 곳의 수치는 미세하게 바뀝니다.

하지만 우리가 다루는 데이터 관점에서는 0.46081...이나 0.46082...나 모델이 예측하는 실용적인 성능에는 거의 차이가 없는 안정권에 들어온 것입니다.

3. 리지 규제(Ridge)의 특성
리지 규제에서 r(알파) 값은 0에서 벗어나기만 하면 일단 폭발을 막아주는 안전장치 역할을 톡톡히 합니다.

다만 r을 터무니없이 너무 크게(예: 100이나 1000처럼) 키워버리면, 모델이 너무 짓눌려서 가중치가 전부 0에 가까워지거나 학습 능력이 망가집니다.

지금처럼 0.001이나 0.01 같은 작은 값들 사이에서는 "폭발만 막아주면 되므로" 결과가 대동소이하게 나오는 것이 지극히 정상입니다!

핵심 요약

다중공선성(Multicollinearity) 문제: 피처 간의 선형 종속 관계로 인해 역행렬이 불안정해지고 가중치가 폭발하는 현상을 확인했습니다.

리지 규제(Ridge Regularization) 적용: 그램 행렬의 대각선에 작은 값(r)을 더해줌으로써 수치적 안정성을 확보하고, 모델의 성능(RMSE)을 대폭 개선할 수 있었습니다.

2.14 Tuning the model (모델 튜닝) 초보자 지침

이 지침은 머신러닝 줌캠프 세션 2의 2.14 Tuning the model 강의 내용을 바탕으로, 노트북 작성과 코드 이해를 돕기 위해 작성되었습니다.

학습 목표
이전에 배운 리지 규제(Ridge Regularization)에서 규제 강도(r)를 어떻게 설정하느냐에 따라 모델의 성능이 달라집니다.

이번 섹션에서는 검증 데이터셋(Validation Set)을 활용하여, 모델을 가장 안정적이고 정확하게 만들어 주는 최적의 규제 하이퍼파라미터 r 값을 찾는 과정을 배웁니다.

개념 이해: 규제 강도(r) 튜닝과 검증

하이퍼파라미터 튜닝(Hyperparameter Tuning): 모델이 학습하는 가중치가 아니라, 사람이 직접 세팅해주어야 하는 값(여기서는 규제 강도 r)을 여러 개 바꿔가며 가장 좋은 성능을 내는 값을 찾는 작업입니다.

검증 세트 활용 (Validation Set): r 값을 0부터 10까지 다양하게 테스트해 보면서, 학습 데이터에만 과하게 맞춰지지 않고 실제 모르는 데이터(검증셋)에서도 오차가 가장 적은(RMSE가 가장 낮은) 최적의 지점을 고릅니다.

실습 코드 및 셀 내러티브
[셀 1] 여러 규제 강도 r을 순회하며 검증 RMSE 비교하기
다양한 r 값들을 리스트로 두고 반복문을 돌며, 각 규제 강도에 따라 학습된 모델의 성능(RMSE)을 측정합니다.

Python
# 여러 규제 강도 r을 돌아가며 검증 RMSE를 비교합니다.
# 너무 작으면 불안정하고, 너무 크면 과소적합이 되므로, 가운데에서 좋은 r을 고릅니다.
for r in [0.0, 0.00001, 0.0001, 0.001, 0.1, 1, 10]:
    X_train = prepare_X(df_train)
    w0, w = train_linear_regression_reg(X_train, y_train, r=r)
    
    X_val = prepare_X(df_val)
    y_pred = w0 + X_val.dot(w)
    score = rmse(y_val, y_pred)
    
    # r, 절편, 검증 점수를 한 줄에 출력해 표처럼 비교합니다.
    print(r, w0, score)

2.15 Using the model (최종 모델 사용) 초보자 지침

이 지침은 머신러닝 줌캠프 세션 2의 2.15 Using the model 강의 내용을 바탕으로, 노트북 작성과 코드 이해를 돕기 위해 작성되었습니다.

학습 목표
앞선 섹션에서 최적의 규제 강도(r)를 찾았습니다. 이제 학습에 사용하지 않고 남겨두었던 테스트 세트(Test set)를 사용하여 모델의 최종 성능을 객관적으로 평가하고, 실제 서비스 상황처럼 새로운 데이터(차량 정보)가 들어왔을 때 가격을 예측하는 방법을 배웁니다.

개념 이해: 최종 모델 학습과 추론
전체 학습(Full Training): 모델을 최대한 똑똑하게 만들기 위해, 검증용으로 떼어두었던 데이터까지 훈련 데이터에 합쳐서 최종 모델을 다시 학습시킵니다.

일반화 성능 확인: 학습에 전혀 쓰이지 않았던 테스트 세트로 모델을 평가하여, 모델이 학습 데이터뿐만 아니라 새로운 데이터에서도 잘 동작하는지(일반화 능력)를 검증합니다.

>>> 여기까지

실전 예측(Inference): 실제 서비스에서는 데이터셋이 아니라, 사용자로부터 입력받은 '단일 딕셔너리(차량 정보)'를 받게 됩니다. 이를 모델이 이해할 수 있는 행렬 형태로 변환하여 예측값을 뽑아내는 과정을 시뮬레이션합니다.

Python

# 하이퍼파라미터 r을 고른 뒤에는, 훈련과 검증을 합쳐 데이터를 최대한 활용합니다.
# concat은 두 데이터프레임을 행 방향으로 이어 붙입니다.
df_full_train = pd.concat([df_train, df_val])

# 이어 붙인 표의 행 번호를 0부터 다시 매깁니다.
df_full_train = df_full_train.reset_index(drop=True)


# 로그 가격 타깃도 훈련+검증 순서로 이어 붙입니다.
# concatenate는 넘파이 배열을 길이 방향으로 합칩니다.
y_full_train = np.concatenate([y_train, y_val])

# 고른 최적의 r=0.001로 모델을 최종 학습합니다.
# 고른 r=0.001로, 합친 데이터에서 가중치를 다시 학습합니다.
# 검증 세트는 이미 r을 고르는 데 썼으므로, 최종 평가는 남겨 둔 테스트 세트에서 합니다.

코드 설명: pandas의 concat과 numpy의 concatenate를 사용하여 분리되어 있던 데이터들을 하나로 합칩니다. 이후 찾았던 최적의 r=0.001을 사용하여 전체 데이터에 대해 최종 가중치를 학습시킵니다.

1. 예측의 정확성과 실용성

2. 일반화 성능의 검증 (과적합되지 않음)
이 차량(df_test.iloc[20])은 모델이 학습할 때 단 한 번도 본 적 없는 완전히 새로운 테스트 데이터입니다.

즉, "우리 모델이 새로운 자동차를 보았을 때 뇌피셜이 아니라 제법 상식적이고 쓸모 있는 중고가 견적을 뽑아낼 수 있다"는 것을 이 숫자가 증명해 주는 것입니다!

개념 이해: 세션 2 핵심 총정리
EDA와 타깃 변수 변환: 데이터를 눈으로 확인하고 결측치를 찾으며, 긴 꼬리(Long-tail) 형태의 가격 분포를 로그 변환을 통해 정규분포(종 모양)에 가깝게 펴주는 전처리의 중요성을 배웠습니다.
