1. 셀 1: 프로젝트 개요 및 문제 정의 (Markdown 셀)
내러티브: 통신사 고객 데이터를 활용해 고객이 서비스를 해지할지 여부를 예측하는 비즈니스 시나리오를 이해합니다. 과거 데이터를 바탕으로 각 고객에게 이탈 확률 점수를 부여하고, 마케팅 프로모션을 통해 이탈을 막는 전략을 세웁니다.

이탈(Churn)이란?: 고객이 우리 회사(통신사) 서비스(전화, 인터넷, TV 등) 이용을 중단하고 다른 경쟁사로 떠나는 것을 의미합니다.

비즈니스 목적: 고객의 이탈 확률을 미리 예측하여, 이탈 위험이 높은 고객에게 할인이나 프로모션(예: 25% 할인) 메일을 보내 이탈을 방지합니다.

핵심 트레이드오프 (정확성의 중요성):

이탈하지 않을 고객에게 불필요한 할인을 주면 회사의 수익이 악화됩니다.

반대로 이탈할 고객을 놓치면 고객을 잃게 됩니다. 따라서 정확한 타겟팅이 필수적입니다.

머신러닝 접근법 (이진 분류):

지도학습(Supervised Learning) 중 분류(Classification), 그중에서도 결과가 0 또는 1로 나뉘는 이진 분류(Binary Classification)를 사용합니다.

수식 표현: g(xi) = yi (여기서 xi는 i번째 고객의 특성 벡터, yi는 0 또는 1인 타겟 변수)

모델 출력값: 0과 1 사이의 이탈 확률 점수(Likelihood) (예: 0.85는 이탈 확률 85%)

나> astype(int)안해도 불리언은 0, 1아닌가 

GEM> 파이썬에서 불리언(Boolean) 타입인 True와 False는 내부적으로 정수 1과 0으로 취급되기 때문에 사칙연산(예: True + True = 2)은 가능합니다.

하지만 판다스(Pandas) 시리즈나 넘파이 배열에서 불리언 값을 정수형 머신러닝 알고리즘이나 통계 계산에 직접 넣었을 때, 라이브러리에 따라 데이터 타입이 bool로 유지되어 예상치 못한 경고(Warning)나 타입 에러가 발생할 수 있습니다.

특히 명시적으로 .astype(int)를 붙여주면 다음과 같은 이점이 있습니다.

명확한 타입 보장: 데이터의 타입이 확실한 정수(int64 또는 int32)로 고정되어, 향후 모델 학습 시 데이터 타입 문제로 인한 오류를 원천 차단합니다.

가독성 및 의도 표현: 이 열이 단순 참/거짓 판단용이 아니라 머신러닝의 수치형 타깃 변수(0과 1)임을 코드 상에서 명확히 드러냅니다.

Python
# train_test_split: 표를 무작위로 여러 덩어리로 나눌 때 쓰는 sklearn 함수다.
# 모델을 '연습(train) / 점검(validation) / 최종시험(test)'에 쓰기 위해 나눈다.
from sklearn.model_selection import train_test_split

2. 셀 10: 데이터 2단계 분할 (Train, Validation, Test)
내러티브: 전체 데이터셋을 60:20:20 비율로 나눕니다. 먼저 전체의 20%를 테스트 세트로 분리하고, 나머지 80%(full_train)에서 다시 25%를 검증 세트로 떼어냅니다(80%의 25%는 전체의 20%가 됨). random_state를 설정하여 코드를 다시 실행해도 항상 같은 결과가 나오도록 고정합니다.

내러티브: 그룹 이탈률을 전체 이탈률로 나눈 값인 위험비(Risk Ratio)를 계산합니다. 이 값이 1보다 크면 평균보다 이탈 위험이 높은 그룹(예: 파트너가 없는 경우)임을 뜻하고, 1보다 작으면 안전한 그룹임을 상대적인 수치로 표현해 줍니다.

Python

# 1보다 크면 그 그룹은 평균보다 이탈 위험이 높다. 파트너 없음은 보통 > 1.
churn_no_partner / global_churn

결과:

# 1보다 작으면 평균보다 안전. 파트너 있음은 보통 < 1.

6. 셀 33~34: 모든 범주형 변수에 대한 자동화 분석 (이탈률, 차이, 위험비)

SELECT
    gender,
    AVG(churn),
    AVG(churn) - global_churn AS diff,
    AVG(churn) / global_churn AS risk
FROM
    data
GROUP BY
    gender;


내러티브: 반복문과 groupby, agg 함수를 활용해 모든 범주형 변수(categorical)에 대해 그룹별 명수, 평균 이탈률, 글로벌 이탈률과의 차이(diff), 그리고 위험비(risk)를 한꺼번에 계산합니다. IPython의 display 함수를 사용하여 주피터 노트북 환경에서 깔끔한 표 형태로 결과를 출력합니다.


Python
# display: 노트북에서 DataFrame을 표 모양으로 보여줄 때 쓴다. print()는 글자로 깨져 보인다.
from IPython.display import display

# 모든 범주형 열에 대해, 값마다 이탈률·건수·차이·위험비를 표로 만든다.
for c in categorical:
    print(c)
    # groupby(c): 그 열의 값별로 묶을 때 쓴다. SQL의 GROUP BY와 같다.
    # .churn.agg(['mean','count']): 묶음마다 평균(이탈률)과 명수를 한 번에 구할 때 쓴다.
    df_group = df_full_train.groupby(c).churn.agg(['mean', 'count'])
    # 전체 대비 차이. 양수면 그 범주는 전체보다 이탈이 높다.
    df_group['diff'] = df_group['mean'] - global_churn
    # 위험비. 1보다 크면 평균보다 위험한 범주 (예: month-to-month, fiber_optic).
    df_group['risk'] = df_group['mean'] / global_churn
    display(df_group)
    print()
    print()

[실습 가이드] 3.6 특성 중요도 분석: 상호 정보량 (Mutual information)


Mutual information - concept from information theory, it tells us how much we can learn about one variable if we know the value of another

https://en.wikipedia.org/wiki/Mutual_information


이번 세션의 목표는 정보 이론에 기반한 상호 정보량(Mutual Information) 개념을 활용하여, 범주형 특성들이 고객 이탈 여부(churn)를 예측하는 데 각각 얼마나 유용한지 상대적인 중요도를 수치로 측정하고 정렬하는 것입니다.

1. 셀 35: 상호 정보량 함수 임포트
내러티브: 두 범주형 변수가 서로에 대해 얼마나 많은 정보를 공유하는지(관련의 세기) 계산하기 위해 Scikit-Learn에서 mutual_info_score 기능을 불러옵니다. 이 값이 클수록 해당 특성이 이탈 예측에 더 많은 단서를 제공한다는 뜻입니다.

[실습 가이드] 3.7 특성 중요도 분석: 상관계수 
Feature importance: Correlation

이번 세션의 목표는 수치형 특성들과 타겟 변수(churn) 간의 선형적 관계와 의존 정도를 측정하기 위해 피어슨 상관계수(Pearson Correlation Coefficient)를 구하고, 이를 통해 수치형 변수의 상대적 중요도를 파악하는 것입니다.

//
나> 이전엔 의존정도/상관관계를 구했을뿐 선형적 관계는 다루지 않은거 맞지?

GEM> 맞습니다. 정확하게 짚으셨습니다!

이전 세션(3.6 상호 정보량)에서 다룬 상호 정보량(Mutual Information)은 변수들 간의 선형 관계뿐만 아니라 비선형적인 복잡한 관계까지 포함하여 "두 변수가 서로 얼마나 많은 정보를 공유하는가(의존 정도)"를 측정하는 지표입니다.

반면, 이번 세션에서 다루는 피어슨 상관계수(Pearson Correlation Coefficient)는 변수들이 직선 형태의 선형적 관계(Linear Relationship)를 띠는지, 그리고 그 방향이 양(+)인지 음(-)인지 측정하는 방식입니다.


나> 그럼 이전방식이 더 범용성 있고 좋은거 아닌가

GEM> 맞습니다. 질문하신 대로 상호 정보량(Mutual Information)이 수학적으로 훨씬 범용적이고 강력한 지표입니다.

그 이유는 다음과 같습니다.

비선형 관계 포착: 데이터의 관계가 직선(선형)이 아니라 곡선이나 U자 형태 등 복잡한 비선형 형태여도 그 연관성을 잡아낼 수 있습니다. 반면 상관계수는 오직 '직선적인 관계'만 측정합니다.

다양한 데이터 타입: 범주형 변수와 범주형 변수, 혹은 범주형과 수치형 간의 관계 등 다양한 조합에 유연하게 적용할 수 있습니다.

그럼에도 불구하고 현업이나 분석 과정에서 상관계수를 함께 사용하는 이유는 다음과 같은 실용적 장점 때문입니다.

직관적인 방향성(+ / -): 상호 정보량은 항상 0 이상의 값만 나오기 때문에 "증가할수록 이탈이 늘어난다(양의 관계)" 또는 "줄어든다(음의 관계)" 같은 방향성을 알 수 없습니다. 반면 상관계수는 -1에서 +1 사이의 값을 가지므로 관계의 방향을 한눈에 파악할 수 있습니다.

/

출력 결과를 다시 확인해 보시면 모든 값이 양수로 되어 있습니다.

Python

dtype: float64
상호 정보량은 정보 이론의 '엔트로피(Entropy)' 개념을 바탕으로 계산되기 때문에, 두 변수가 정보를 전혀 공유하지 않을 때 최솟값인 0이 되고, 연관성이 높을수록 계속 커지는 구조를 가집니다.

따라서 마이너스(-) 기호가 붙어서 '값이 증가할수록 타겟이 감소한다(음의 관계)'라는 방향성을 알려주는 지표는 상호 정보량이 아니라 상관계수입니다.


나> 예를 들어:

GEM> 아, 보여주신 출력 결과는 앞서 3.5절에서 다뤘던 위험비(Risk Ratio)와 이탈률 차이(diff)가 포함된 표의 일부입니다!

여기서 -0.027698처럼 마이너스(-) 부호가 붙은 값은 상호 정보량이 아니라 글로벌 이탈률과 해당 그룹 이탈률의 차이(diff)입니다.

의미: 이 값이 음수(-)라는 것은 "해당 그룹의 이탈률이 전체 평균 이탈률보다 낮다"는 뜻입니다. (예: 어떤 특성을 가진 그룹은 평균보다 이탈이 적음)

상호 정보량(MI)과의 차이: MI는 방향성이 없지만, 3.5절에서 구한 diff나 위험비(risk), 그리고 이번 3.7절의 correlation은 모두 방향성(증가하는지, 감소하는지)을 보여준다는 공통점이 있습니다.

[실습 가이드] 3.9 로지스틱 회귀 (Logistic Regression)

이번 세션의 목표는 고객 이탈 여부처럼 참(1) 또는 거짓(0)을 판별하는 이진 분류(Binary Classification) 문제를 풀기 위해 로지스틱 회귀(Logistic Regression)의 기본 개념과 핵심 구성 요소인 시그모이드 함수(Sigmoid Function)를 이해하는 것입니다.

1. 셀 54: 시그모이드 함수 정의
내러티브: 선형 회귀는 결과값으로 무한대의 실수를 뱉어내기 때문에 확률로 쓰기 어렵습니다. 따라서 어떤 실수든 0과 1 사이의 값으로 압축하여 '확률'처럼 다룰 수 있도록 시그모이드 함수를 정의합니다. 자연상수 e를 활용한 지수 연산으로 구현됩니다.

Python
# sigmoid: 아무 실수 z를 0과 1 사이로 눌러 '확률처럼' 만들 때 쓴다.
# 로지스틱 회귀 = 선형 점수(가중합) 후에 이 함수를 씌워 이탈 확률을 낸다.
# np.exp: 자연상수 e의 거듭제곱. 선형회귀는 점수가 무한대일 수 있어서 확률이 아니다.
def sigmoid(z):
    return 1 / (1 + np.exp(-z))

내러티브: 시그모이드 함수의 모양을 시각적으로 확인하기 위해, 영(0)을 중심으로 좌우 넓은 범위(-7부터 7까지)를 균등한 간격의 점 51개로 쪼개어 가로축 값(z)을 준비합니다.

# linspace(시작, 끝, 개수): 구간을 균등한 점들로 나눌 때 쓴다. 그래프의 가로축 z.

# 아주 큰 양수 → 시그모이드는 1에 수렴. '점수가 크면 확률 거의 100%'를 확인한다.

# 선형 회귀 점수를 손으로 쓴 개념 코드다. 가중합 + 절편.
# 이 셀을 지금 실행하면 w0, w 가 아직 없어서 NameError 가 난다. (작은 모델을 학습한 뒤에 생긴다)

6. 셀 59: 수동 구현한 로지스틱 회귀 함수 뼈대
내러티브: 선형 회귀로 구한 점수(가중합)에 앞서 정의한 sigmoid 함수를 최종적으로 씌워 0과 1 사이의 확률 값을 도출하는 로지스틱 회귀의 전체 흐름을 구조화합니다.

Python
# 로지스틱 회귀: 선형 점수에 sigmoid를 씌워 확률을 낸다. 선형회귀와의 차이점이다.

[실습 가이드] 3.10 Scikit-Learn으로 로지스틱 회귀 모델 학습하기

//
나> 시그모이드가 로지스틱 함수?
GEM> 네, 맞습니다!

수학적으로 시그모이드 함수(Sigmoid Function)의 가장 대표적이고 널리 쓰이는 형태가 바로 로지스틱 함수(Logistic Function)입니다.

'시그모이드'라는 단어는 원래 모양이 S자형(Sigma-shaped)인 모든 곡선을 통틀어 부르는 넓은 개념입니다.

그중에서 우리가 기계학습(로지스틱 회귀)에서 쓰는 1 / (1 + exp(-z)) 형태의 함수를 정확히 로지스틱 함수라고 부릅니다.

따라서 머신러닝 맥락에서는 보통 시그모이드 함수 = 로지스틱 함수로 혼용해서 사용해도 무방합니다.
//


이번 세션의 목표는 Scikit-Learn을 사용해 로지스틱 회귀 모델을 학습시키고, 검증 데이터셋에 적용한 뒤 모델의 예측 성능을 정확도(Accuracy)로 평가하는 것입니다.

1. 셀 60: 로지스틱 회귀 모델 객체 생성 및 학습
내러티브: Scikit-Learn의 선형 모델 패키지에서 로지스틱 회귀 분류기를 가져옵니다. solver='lbfgs'와 충분한 반복 횟수(max_iter=1000)를 설정한 뒤 fit 메서드를 호출하여 훈련 데이터(X_train, y_train)로부터 가중치와 절편을 학습시킵니다.

Python
# LogisticRegression: sklearn이 구현한 로지스틱 회귀 분류기다. 내부에서 시그모이드+가중치 학습을 한다.
from sklearn.linear_model import LogisticRegression

# solver='lbfgs': 가중치를 찾는 최적화 알고리즘. 최근 sklearn 기본값이다.
# max_iter=1000: 최대 반복 횟수. 기본 100이면 이 데이터에서 종종 수렴을 못 한다.

2. 셀 61: 모델의 편향(절편) 확인
내러티브: 학습된 모델의 기준점인 절편(intercept_)을 확인합니다. 이진 분류에서 [0]은 클래스 1(이탈)에 해당하는 로그오즈(Log-odds) 기준값을 의미합니다.

//
나> "이진 분류에서 [0]은 클래스 1(이탈)에 해당하는 로그오즈(Log-odds) 기준값을 의미합니다."

뭔말이야

GEM> 이 내용은 로지스틱 회귀 모델이 내부적으로 계산하는 점수(로그오즈)와 그것이 의미하는 바를 설명하는 말입니다. 이해하기 쉽게 두 부분으로 쪼개서 설명해 드릴게요.

1. 로그오즈(Log-odds)란 무엇인가요?
오즈(Odds): "어떤 일이 일어나지 않을 확률 대비 일어날 확률"을 뜻합니다. (예: 이탈할 확률 / 유지할 확률)

로그오즈(Log-odds): 그 오즈 값에 자연로그(ln)를 씌운 것입니다.

로지스틱 회귀는 선형 회귀처럼 껍데기는 똑같이 가중합(w0 + w1*x1 + ...)을 계산하는데, 이 계산 결과로 나오는 숫자가 바로 확률이 아니라 로그오즈(점수)입니다. 이 점수가 높을수록 "이탈할 가능성이 크다"는 뜻이 됩니다.

2. 왜 [0]을 붙여서 보나요? (model.intercept_[0])
다중 클래스 분류(예: A, B, C 클래스 분류)를 할 때 모델은 각 클래스별로 점수(절편이나 가중치)를 여러 개([0], [1] 등) 가집니다.

지금 우리가 푸는 문제는 '이탈(1)'이냐 '유지(0)'냐를 맞히는 이진 분류(Binary Classification)입니다.

Scikit-Learn의 이진 분류 로지스틱 회귀는 내부적으로 0번 클래스(유지)와 1번 클래스(이탈)를 구분하는데, 그중 기준이 되는 양성 클래스(여기서는 클래스 1인 '이탈')에 해당하는 로그오즈 절편 값을 꺼내오기 위해 [0](첫 번째 요소)을 붙여서 확인하는 것입니다.
//

Python
# intercept_: 절편 w0. 특성이 모두 0일 때의 기준(로그오즈).
# [0]은 이진 분류에서 '클래스 1(이탈)'에 해당하는 값이다.
model.intercept_[0]

임계값에 따른 성능 평가 (ROC, AUC 등):

모델이 0.85로 예측해서 맞힌 것과, 0.51로 겨우겨우 턱걸이로 맞힌 것은 모델의 '확신 수준'이 다릅니다. 이 확률의 분포를 보고 모델이 얼마나 일을 잘하는지 종합적으로 평가(ROC 곡선 그리기 등)할 때 이 probability가 핵심 재료로 쓰입니다.

즉, "당장 이번 셀에서는 안 쓰이지만, 모델의 확신 정도를 보관해 두었다가 나중에 기준을 바꾸거나 정밀한 평가 지표를 계산할 때 쓰려고 미리 담아둔 것"입니다.

구체적으로 어떤 차이가 있는지 쉽게 정리해 드릴게요.

y_val (진짜 정답):

y_pred (predict_proba 결과):

나> y_pred 코드 원리/성질 노이해

1. predict_proba의 원리: "확률을 뱉어내는 자판기"

sparse=True (기본값):

머신러닝 모델(예: LogisticRegression)에 데이터를 집어넣거나, 우리가 직접 행렬 데이터를 눈으로 확인하고 조작할 때는 압축된 형태보다 일반적인 2차원 배열이 훨씬 다루기 편하기 때문에 sparse=False로 풀어주는 것입니다.

나> 작동원리

GEM> dv_small.transform(dicts_train_small)이 작동하는 원리는 이미 fit 단계에서 학습해 둔 범주별 규칙(사전)을 바탕으로, 딕셔너리 데이터를 머신러닝이 이해할 수 있는 숫자 행렬(0과 1, 그리고 숫자 값)로 변환하는 것입니다.

구체적인 작동 방식은 다음과 같습니다.

사전(Vocabulary) 대조:

앞서 dv_small.fit(dicts_train_small)을 할 때 dv_small은 데이터에 어떤 범주(예: contract=month-to-month, contract=two_year 등)가 존재하고 각각이 몇 번째 열을 차지해야 하는지 규칙(기준표)을 만들었습니다.

transform은 이 만들어진 기준표를 그대로 가져와서 사용합니다. 새로 규칙을 만들지 않고 고정된 기준표에 맞추기만 하는 것이 핵심입니다.

벡터화(Vectorization):

입력으로 들어온 딕셔너리 리스트(dicts_train_small)의 각 행을 돌면서, 기준표의 항목에 해당하면 1, 아니면 0을 채워 넣습니다.

//
나> 그럼 기준표와 입력의 값이 다를 수 있다는 거야?

GEM> 네, 정확히 보셨습니다! 기준표(fit할 때 본 데이터)에 없던 새로운 값이 입력(transform할 때 넣은 데이터)에 들어오면, transform은 그 값을 아예 무시(없는 취급)해 버립니다.

이 때문에 실무나 머신러닝 실습에서 아주 중요한 문제가 생기는데요. 구체적인 동작 방식은 이렇습니다.

1. 기준표에 없는 새로운 값이 들어올 때
만약 학습(train) 데이터에는 없던 특성값(예: 새로운 계약 형태나 신규 지역명 등)이 검증(val) 데이터나 테스트 데이터에 포함되어 있다면, transform은 이미 만들어진 기준표에 해당 항목이 없기 때문에 그 값을 무시하고 전부 0 처리해 버립니다.

반대로 학습 데이터에는 있었는데 검증 데이터에 없으면, 해당 열은 그냥 0으로 채워집니다.

2. 왜 fit과 transform을 분리(또는 엄격하게 관리)해야 하는지?
학습(train) 데이터로 fit을 할 때는 모델이 "아, 우리 데이터에는 이런 종류의 카테고리들이 있구나!" 하고 기준표(전체 어휘 사전)를 만듭니다.

그래서 "학습 데이터로 만든 고정된 기준표(fit)를 바탕으로, 검증/테스트 데이터는 오직 변환만(transform) 해야 한다"는 원칙이 철저하게 지켜지는 것입니다.

'fit과 분리한 예'가 의미하는 것

fit과 transform을 한 번에 처리하는 함수도 존재합니다.

3.13 Summary (세션 3 총정리 가이드)
머신러닝 줌캠프 세션 3(분류를 위한 머신러닝)의 마지막 요약 섹션입니다. 이번 장에서 다룬 전체 고객 이탈 예측 프로젝트의 핵심 개념들을 되짚어봅니다.

1. 데이터 준비 및 검증 프레임워크 (Data Preparation & Validation)
내러티브: 텔레콤 회사 고객들의 이탈 여부를 예측하기 위해 캐글 데이터셋을 활용했습니다. 고객의 인구통계학적 정보, 이용 중인 서비스, 계약 형태 등 다양한 데이터를 정제하고, 사이킷런을 이용해 데이터를 학습(Train)·검증(Validation)·테스트(Test) 세트로 나누어 안정적인 검증 프레임워크를 구축했습니다.

2. 특성 중요도 분석 (Feature Importance)
모델을 만들기 전, 어떤 변수가 이탈에 큰 영향을 미치는지 세 가지 방법으로 분석했습니다.

리스크 비율 (Risk Ratio): 특정 그룹의 고객들이 전체 평균에 비해 얼마나 더 이탈하기 쉬운지 비교하여 인사이트를 얻었습니다.

상호 정보량 (Mutual Information): 범주형 변수가 이탈 여부에 대해 얼마나 유용한 정보를 주는지 수치화했습니다. (예: contract 계약 형태가 gender 성별보다 이탈 예측에 훨씬 중요한 변수임을 확인)

상관계수 (Correlation Coefficient): 수치형 변수와 이탈 간의 선형적 관련성을 측정했습니다. (양의 상관관계면 이탈률 증가, 음의 상관관계면 이탈률 감소)

3. 원-핫 인코딩과 로지스틱 회귀 (One-Hot Encoding & 
Logistic Regression)

원-핫 인코딩 (DictVectorizer): 컴퓨터가 글자 형태의 카테고리 데이터를 이해할 수 있도록 여러 개의 독립된 0과 1의 컬럼으로 쪼개는 전처리 과정을 사이킷런의 DictVectorizer로 구현했습니다.

로지스틱 회귀 (Logistic Regression): 0 또는 1(이탈 혹은 유지)을 판별하는 이진 분류(Binary Classification) 문제를 풀기 위한 핵심 모델입니다. 선형 회귀와 유사하지만, 출력값에 시그모이드 함수(Sigmoid)를 통과시켜 모든 점수를 0과 1 사이의 확률 값으로 변환해 준다는 점이 가장 큰 특징입니다.

4. 모델 해석 및 최종 활용 (Model Interpretation & Usage)
가중치 해석: 선형 회귀와 마찬가지로 로지스틱 회귀의 가중치(계수) 부호와 크기를 통해 각 특성이 이탈에 미치는 영향력을 해석했습니다.

최종 모델 학습 및 테스트: 전체 학습 데이터(Full Train)로 최종 모델을 학습시킨 뒤, 한 번도 보지 않은 테스트 세트(test)를 통해 정확도(Accuracy)가 약 80% 수준으로 안정적으로 작동함을 검증했습니다.

실제 고객 예측: 단일 고객의 딕셔너리 데이터를 모델에 집어넣어 이탈 확률을 계산하고, 이를 바탕으로 프로모션 이메일 발송 여부 등의 비즈니스 의사결정에 활용하는 전체 파이프라인을 완성했습니다.

다음 세션 예고: 지금까지는 모델의 성능을 평가할 때 '정확도(Accuracy)'만 사용했지만, 다음 세션에서는 **"과연 80%라는 정확도가 실제로 좋은 것인지?", "클래스가 불균형할 때 정확도 외에 어떤 지표(정밀도, 재현율, ROC AUC 등)로 모델을 평가해야 하는지"**를 다루게 됩니다.

Bash
export UV_PYTHON_INSTALL_DIR="E:/IT_SPACES/AI/.cache/uv-python"

이 명령어를 실행하시면 모듈 02와 정확히 동일한 환경(nbclassic)으로 notebook.ipynb가 즉시 기동됩니다. 바로 진행해 보세요!




나> 이거 왜케 많아? 그냥 jupyter notebook 이 명령어 하나로 실행되게 하는 방법 없어?

CUR + GEM> 잭카드님, 커서의 설명처럼 명령어가 길었던 이유는 C 드라이브 아나콘다(anaconda3)로 경로가 새어나가는 것을 막고, 모듈 02에서 검증된 공유 venv의 nbclassic을 정확하게 짚어서 실행하기 위해서였습니다.

하지만 매번 긴 명령어를 치거나 여러 줄을 복사하기 번거로우시다면, 원하시는 대로 한 줄 또는 간단한 명령어로 실행할 수 있는 방법이 있습니다.

방법 1: 가장 깔끔한 한 줄 명령 (Git Bash)
현재 notebook 폴더로 이동한 상태이거나 경로를 포함해서 아래 한 줄만 입력하시면 바로 실행됩니다.

Bash
"/e/IT_SPACES/AI/ZoomCamp/ML/.venv/Scripts/python.exe" "/e/IT_SPACES/AI/ZoomCamp/ML/.venv/Scripts/jupyter-nbclassic-script.py" notebook.ipynb
방법 2: jupyter notebook처럼 짧은 단어로 실행하기 (Alias 등록)
매번 저 긴 경로를 치기 귀찮으시다면, Git Bash에 단축어(Alias)를 등록해 두시면 됩니다. Git Bash 창에 아래 명령을 딱 한 번만 입력해 두세요.

Bash
alias run-ml3='/e/IT_SPACES/AI/ZoomCamp/ML/.venv/Scripts/python.exe /e/IT_SPACES/AI/ZoomCamp/ML/.venv/Scripts/jupyter-nbclassic-script.py notebook.ipynb'
이렇게 등록해 두신 후에는 앞으로 모듈 3 폴더(03/classification/notebook)에서 아래 단어 하나만 치시면 끝납니다.

Bash
run-ml3
어떤 방식이 가장 편해 보이시나요? 편하신 쪽으로 바로 사용하시면 됩니다!




나 to CUR> 점검

CUR + GEM> 가장 깔끔하고 안전하게 실행하는 방법은 커서가 정리해 준 run-nbclassic.sh 스크립트를 호출하는 방식입니다.
